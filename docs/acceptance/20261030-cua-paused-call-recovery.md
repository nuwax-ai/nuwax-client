# Computer Use 暂停调用恢复验收

## 现场与根因

2026-10-30 本地时间，运行中的 Beta.11：

- 12:58:19.356 观察 Nuwax 主窗口，12:58:19.453 以 userTakingControl / retryable=false 返回，提示等待用户恢复。
- 12:58:26.030 模型改为观察浏览器窗口，同一任务仍处于暂停状态。
- 13:03:26.037 返回 `timed out awaiting tools/call after 300s`。

已读取正在使用的 app.asar，确认其 waitReady 使用任务剩余 15 分钟作为等待上限；与上游 300 秒请求超时不匹配。暂停提示、网关等待与模型错误处理没有收敛到同一种状态。

## 本地验证

- 现场回归先红后绿：旧代码的 4 个新增用例在 500ms 观察窗口中仍无响应。
- MCP 网关：43 项通过。真实本地 TCP 连接、模拟 native driver；验证暂停新调用及时拒绝、等待有界、恢复后重新观察、无自动重放、同进程租约等待 drain 后释放、停止/取消只返回一次。
- 商业版：3790 通过、18 跳过；306 文件通过、1 跳过。
- 壳 import boundary、appdir literal、host-bridge snapshot 检查通过。
- Electron 页面：240×152 的单窗口及 264×176 的四层预览。默认操作栏 opacity=0 / pointer-events=none，悬停或键盘聚焦为 opacity=1 / pointer-events=auto，移出后隐藏；暂停标签可见。
- 浅色、深色、默认、悬停、暂停、键盘和堆叠图像的边缘 alpha≤1，确认透明留白容纳阴影。测试使用焦点模拟，不抢占用户桌面焦点。

## Writer 质量自查

1. 内聚：`mcpGateway.ts` 统一等待上限和单次响应，`taskRegistry.ts` 保留任务预算与订阅清理；不在各按钮中实现工具重试。
2. 分层：改动局限主进程 Computer Use 与私有预览页；MCP 提示在 Guidance/Policy，未新增网页授权能力。
3. 可维护：等待上限有具名常量，响应结束与原生 drain 分开，回归覆盖同进程租约和重复响应风险。

结论：本地源码质量门通过，可进入 Beta 构建；不是 PR approve，也不替代五平台安装包和实机验收。
