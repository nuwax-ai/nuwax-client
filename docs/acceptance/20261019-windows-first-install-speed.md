## 实现与瓶颈

锁定的 electron-builder / app-builder-lib 25.1.8 中，`extractAppPackage.nsh` 的 7z 路径先将内嵌归档展开到 `$PLUGINSDIR\7z-out`，再 `CopyFiles` 整树到安装目录；ZIP 路径通过 `nsisunz::Unzip` 直接写入 `$INSTDIR`。候选启用成对的 `differentialPackage:false`、`useZip:true`，去掉重复的完整载荷写入。

ZIP 模式同时会关闭 SDK 原本生成的 EXE blockmap。因此在 `afterAllArtifactBuild` 中对最终 EXE 生成外部 `.blockmap`，验证 gzip v2、块范围及 EXE SHA512，生成过程不改写安装器。现有 electron-updater 6.8.3 已通过 HTTP Range 与缓存文件重建回归；真实安装后的更新器缓存仍待核验。

最高 ZIP 压缩在真机持续约 18 分钟仍未完成，已主动停止该次构建，未用于计时。候选改为 SDK 的 `normal`（7z ZIP 参数 `-mx=7`，不带 `-mpass=15`），API 与旧 dist 入口共用策略；保留显式 `7z-qa` 对照。包体增加量、下载代价须与实测安装收益一并记录。

未改变应用主进程/渲染器源码、资源集合、三个 gitlink、安装身份、保全/卸载逻辑、签名或公开发布保护。

## 实际包基线

测试机为原生 Windows 11 x64（26200）、Ryzen 7 5700U、约 31.4 GiB 内存、ZHITAI TiPlus7100 SSD；Defender 杀毒和实时防护均开启。不是 ARM 仿真结果。

为保护日常客户端，使用独立 QA appId、`NuwaxInstallSpeedQA` 可执行文件与卸载登记、专用更新器缓存，以及 `C:\nuwax-qa\first-install-20261019` 自有目录。载荷来自已校验公开 SHA256 的 beta.7；它与 3.1 当前应用/前端/产物 pins 一致。只修改 QA 元数据、启动入口与禁用公开更新的配置，原 ASAR 55 个拆包项保持，19,771 个原始应用文件的尺寸/拆包标志/内容 hash 一致。QA bootstrap 在加载原主进程前隔离 profile；尚未执行启动验收。

7z 基线保留公开包原压缩块，仅替换 QA ASAR/配置和可执行文件路径。ZIP 候选使用同一份解包载荷。NSIS 使用当前 3.1 安装/卸载 include；仅复制到 QA 工具链的模板加入阶段时间戳，不修改仓库中的安装器模板或 SDK 依赖。
