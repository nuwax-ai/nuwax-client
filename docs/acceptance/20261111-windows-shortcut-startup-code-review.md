# Windows 快捷方式、自启及引擎选择修复评估

本次按用户最新决定收口到代码修复和影响评估，不追加打包、实机或测试运行。PR #110 面向 `release/v3.1.0`，不创建 tag、Release 或更新指针。

## 修复与因果

| 问题 | 原因 | 修改后的逻辑 |
| --- | --- | --- |
| NW-321 / NW-326-2：覆盖升级重建已删除桌面入口 | 旧 EXE 被保全移走后，安装器重新判断为需要创建快捷方式；中断后内存中的保留策略也丢失 | 普通覆盖沿用同目录已登记安装的选择；中断重试从核验过的持久登记快照恢复 KeepShortcuts |
| 中断且安装目录被删除后的登记冲突 | 路径解析先补写登记，改变了恢复校验要对照的存活值 | 有待恢复记录时保持登记只读，交给原恢复流程完成处理 |
| NW-333：关闭自启漏掉历史入口 | 历史 Electron 产品名及含空格名称未被识别 | 补充历史名称识别，继续要求有效 Nuwax.exe 目标及产品所有权；NuwaClaw、Dev 和其他产品保持隔离 |
| 升级后误选旧引擎 | 旧 vendor 目录被保留，运行时按遍历顺序取第一份引擎 | 打包从适配器实际依赖记录 harnessEngineVersion；运行时精确选择该版本，本地联调同步选择该目录 |

## 原有流程的影响评估

- 快捷方式策略继续绑定同一产品、安装目录、安装范围和 Windows 用户；复用原快照完整性与存活登记值校验。初装、不同安装目录和已完成的历史恢复不会继承旧选择。策略缺失或非法时停止安装，保留恢复资料。
- 开始菜单及桌面入口仍由原安装器创建和恢复；此次没有新增一套快捷方式创建流程。普通升级和中断重试共用保留策略。
- 自启仍由现有设置/IPC/产品归属清理流程控制，只补齐历史名称。没有修改默认开关、注册目录、权限提升、NuwaClaw 或其他产品的清理规则。
- 引擎版本来自构建时真实依赖，不写死 0.18.37。未知/缺失的已声明配套版本不会被其他旧版本替代；旧资源没有声明但只有一份引擎时继续可用，多份且无法确定版本时不再猜测。无 bundled 资源时的 npm 缓存定位仍沿用原逻辑。
- 本地 harness 替换和还原使用同一配套目录，避免运行时定位已修复、联调脚本却继续替换旧目录。没有改动本地编译、备份/还原方式或 HARNESS_LOCAL 行为。
- 不删除历史引擎、工作区或用户文件；不修改登录、Cookie、凭据、模型/协议配置、任务生命周期、前端双 pin 或更新通道。原生 helper/capture 缓存配方没有变化。

代码路径评估未发现上述正常流程的额外改变；变化集中于本次缺陷对应的判断和歧义处理。该结论为源码评估，不等于对所有业务场景的实测保证。
