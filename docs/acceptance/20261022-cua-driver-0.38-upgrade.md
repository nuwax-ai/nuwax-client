# cua-driver 更新核查与迁移

2026-10-22 对照 [产品页](https://cua.ai/cua-driver)、[官方 quickstart](https://cua.ai/docs/cua-driver/quickstart)、[0.38.0 发布记录](https://github.com/trycua/cua/releases/tag/cua-driver-rs-v0.38.0) 及对应源码。结论：需要更新原生驱动，现有 Nuwax 产品边界继续保留。

## 版本与范围

- 原构建：0.28.2 / `625118a9076e51da2f57b6a5d475972030197443`（2026-09-16）。
- 本次固定：0.38.0 / `85e2b1318bd77ccf3cfa88ccdf875a4bb7eaed19`。发布页说明 plain SemVer 属稳定渠道；GitHub Pre-release 标签用于避免多产品仓库的 Latest 指针相互覆盖。
- 当天 main 为 `2d5d5d64637d2d2f8f2561c8301403515df826c2`，不作为本候选的浮动输入。
- 相关变化包括 Windows 目标进程归属、滚动坐标、遮挡时拖拽拒绝和输入反馈，macOS 焦点确认、后台拖拽、捕获及会话清理；Cua Spaces、云桌面、自带产品 UI 和 Harness 不属于本次纳入范围。原生 Cargo 内部 sdk crate 随锁定工作区一起编译，不代表加入新的 Agent 产品或要求用户重新配置模型。

## 迁移结果

原商业补丁在 daemon、bundle、history_runtime、main、serve 五个文件不能直接 apply。已按新接口迁移：

1. 私有 endpoint challenge/HMAC 与 capability 校验继续覆盖每条原生请求；macOS helper 的 Team、bundle ID 与稳定安装路径不变。
2. 任务 admit 在 reserved args 清理之前执行，后续 session 归属、结果观察与 permit 释放保持对称；绑定、epoch、revoke/drain、精确接管与独立预览均保留。
3. history、安装及驱动自有状态优先使用宿主数据目录；telemetry 继续显式关闭。
4. 新枚举函数补齐 pid/Spaces 参数；遮挡检查只需当前屏幕窗口，不获取额外 Space snapshot。
5. 构建 sparse checkout 带入新增的 shared telemetry 清单和静态 JSON 输入；本地源码缓存也包含这些输入，避免构建后仍复用旧 helper。
6. Windows 真机构建发现 Git Bash 的 Unix link.exe 遮挡 MSVC 链接器；构建脚本优先使用 vcvars 选择的工具目录，并有失败回归覆盖。
7. 未直接开放上游新增批量/脚本工具，继续由现有工具白名单和任务策略控制；不会绕过每步观察、预算或撤权。

0.38 的 pid-less 失效 element_token 现在返回明确 stale_element_token refusal，替代旧参数校验错误。现有结果分类已能正确识别；协议检查按“确定未执行”的语义接受这两种明确形态。
