## app-update.yml 缺失根因与流程修复

已用锁定的 `electron-builder/app-builder-lib 25.1.8` 实现复现完整缺失路径，回归位于 `scripts/app-update-packaging.test.mjs` 的 `installed builder reproduces missing macOS config with --dir followed by --prepackaged`。测试直接调用实际安装的 `PublishManager`、`Packager.afterPack` 和 `MacPackager.pack`，不复制依赖内部的判断条件。

1. `v3.0.15` 的 `.github/workflows/release-electron.yml:484` 先以 `--dir --publish never --config.mac.notarize=false` 生成并签名 `.app`，随后独立公证。macOS 的 `--dir` 没有 DMG/ZIP target；依赖 `out/publish/PublishManager.js:79-95` 的内置 afterPack 回调检测到这一点直接返回，未写入 `Contents/Resources/app-update.yml`。
2. `v3.0.15` 的 `scripts/release-mac-notarization.mjs:118` 再用 `--prepackaged` 把已公证应用封装成 ZIP/DMG。依赖 `out/macPackager.js:169-173` 在此路径跳过 `doPack`，不会再调用生成文件的 afterPack；缺失状态原样进入分发包。回归同时验证：相同 `--publish never` 下传入 ZIP target 会生成文件，说明关键条件是两阶段打包的 target/hook 路径。
3. 当时上传前检查了捕获资源、签名、公证及来源，没有校验更新配置内容。签名和公证可对缺少该文件的应用成功，因此缺陷未被拦截。
4. 运行期 `electron-updater 6.8.3` 的 `ElectronAppAdapter.js:23` 指向 `process.resourcesPath/app-update.yml`；下载阶段 `AppUpdater.js:542-545` 仍需从此文件读取 `updaterCacheDirName`。因此用户能看到新版信息，却在下载时报 ENOENT。

`v3.0.16@1100cab8e2c53ca422a600369ef8523064029bfb` 已包含以下修复：

- 商业包所有入口共用 afterPack，在 electron-builder 内置回调后、签名前显式写入并校验配置；即使 `--dir` 的 target 为空，也会生成。统一 generic provider、正式 feed 和独立的 `nuwax-updater` 缓存标识。
- 公证前、`--prepackaged` 封装前后只校验文件；缺失或内容不符立即失败，已签名应用不补写。
- stable/beta/QA 上传前验证实际 `.app`、ZIP 内的文件和只读挂载 DMG 中的文件；缺失、错误 provider/feed/cache、截断内容都阻止上传。
- 锁定 builder 的根因复现与修复、hook 顺序、各平台配置、Linux 后置重写以及 ZIP/DMG 检查均有回归。此次新增实际依赖路径复现后，配置专项 6 项通过、0 跳过。

最终公开发布仍须以本次两个 macOS 架构的真实安装包下载核验结果为准。`v3.0.15` 已安装客户端缺少本地文件，需用完整 3.0.16 DMG 替换应用以恢复后续自动更新。
