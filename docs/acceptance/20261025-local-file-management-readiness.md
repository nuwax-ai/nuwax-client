## 实现结果

| 操作 | 当前实现 | 本轮证据 |
| --- | --- | --- |
| 预览 | 恢复 local-files 注册；原流式协议与 HTML 隔离继续生效 | 真实 Electron：GET/HEAD/Range、110MiB、H.264 播放/seek、相对资源与跨 owner 拒绝 |
| 打开/定位 | 复用受信 IPC、实际文件校验与 Electron shell 适配器 | 既有领域回归；本轮未打开用户系统应用 |
| 编辑 | `updateFiles` 通过主进程原子替换文本文件，保留权限；同 runtime 写入串行 | 真实临时文件、真实 IPC 回读；外部变更检查、失败保留原文件 |
| 新增/重命名 | 新建文件/目录，拒绝已有目标；支持大小写改名和目录整体改名 | 文件系统回归及真实 Electron IPC |
| 删除 | 调用 `shell.trashItem`；失败不永久删除；删除链接仅操作链接条目 | 夹具适配器验证内容保留、拒绝跨 owner；真实系统回收站待实包验收 |

本机写路径限定当前会话真实工作区，拒绝工作区根和路径/目录链接越界。导航/登出使排队操作失效。已交给系统的原生动作不承诺撤销；批次逐项提交，不承诺跨文件事务。

前端统一在 `apiUpdateStaticFile` 分流，页面继续使用现有文件面板。API v2 的 writable/updateFiles 与生成快照同步；旧本机只读桥或已确认本机后的失败不会转到云端写入。错误转换为失败返回码和提示，自动保存保留脏内容。上传、ZIP 导入、Git 操作仍走既有路线；列表/搜索仍由主进程访问 loopback file-server，文件字节与写操作由主进程直接处理。
