# beta.8 代码交付与待验范围

用户要求完成代码并打一个 Beta，由用户明天实际验证。本文记录实现与自动化结果，不替代安装包验收。[实施计划](../../plans/20261026-beta6-remediation-plan.md) 保留原始问题与关闭标准。

## 实现

- 通知：只把主窗口和当前准入的业务二级窗视为业务前台，截图/CU、本地辅助窗、外域和失效旧域名不再抑制通知。诊断只记录进程内序号、白名单原因和数值错误码。`submitted` 仅证明系统接受请求，保留后续点击监听，不等同通知中心列表可见。
- 启动恢复：PC Web 使用四态品牌卡片和本地五语言；同步抛错或异步拒绝后重新允许刷新。新增阶段诊断不显示原始错误、地址参数、Cookie、消息或请求体。
- WebView：失败或慢等待立即让首载覆盖层退让；保留当前 guest 等待自然完成，崩溃/解析失败可重建，旧 guest 回调不覆盖新一轮。工具栏和卡片共用刷新锁；服务门禁失败也保留窗口控制与设置。
- 服务门禁：主进程维持单一在途探测，探测时缓存为 null；renderer 先订阅事件再读缓存，忽略旧响应，慢等待时只读复查。IPC 名称、应答和结果形状不变，旧页面兼容。
- Dock：自启动 IPC 备用路径统一使用已有管理器，避免写入隐藏启动策略；恢复请求合并，消费异步拒绝，窗口隐藏/恢复与唤醒/解锁时检查，退出时不重新显示。

## 三问质量自查

1. 内聚：通知前台筛选集中在 `imReceiverRuntime.ts`；生命周期由 `imNativePresentation.ts` 管理；就绪缓存与单一探测收在 `serviceReadinessGate.ts`，观察与迟到结果防护收在 renderer `serviceReadiness.ts`。未建立第二套服务启动链。证据：`imReceiverRuntime.ts:40`、`imNativePresentation.ts:164`、`serviceReadinessGate.ts:4`、renderer `serviceReadiness.ts:22`。
2. 分层：主进程负责服务状态与系统通知，renderer 只观察和发起既有 IPC；恢复卡片只消费展示状态和回调。商业改动通过 overlay，未变更宿主桥契约、登录事实源或本机/远端文件边界。证据：`main.ts:920`、`PageLoadRecovery.tsx:64`、`webviewLoadFailure.ts:18`。
3. 维护：计时器和监听有清理，换域/销毁有代次保护，异常日志白名单化；慢提示不判定后端死亡，重试不无限循环。保留有独立保护价值的竞态与清理回归。证据：`NuwaxHostWebview.tsx:211`、`serviceReadiness.ts:71`、`dockVisibility.ts:18` 及相邻回归。此为 writer 自查，不是 PR 自批。

## 用户待验

1. macOS 后台、主窗关闭、最小化下，真实私聊/群聊进入系统通知中心；横幅结束后仍保留且可点击唤回。权限和 submitted 日志不能替代此项。
2. Mac/Windows 首次重启、文件开关 OFF/ON 后重开；服务慢或网络暂不可达时可恢复，失败页的刷新、设置和窗口按钮可操作。
3. Dock 关闭主窗、隐藏、最小化、自启动、睡眠/解锁和升级后重开。原始间歇问题尚未复现，继续打开。
4. 新旧客户端/网页与浏览器、本机/其他电脑/云端组合；本机文件不存在明确提示，不能错误回退到后端写入。
