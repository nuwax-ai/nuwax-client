# 工程维护约定

## 依赖与源码来源

- 每月检查外层 GitHub Actions、基座 pnpm 依赖、前端 pnpm 依赖及打包下载的 Node/Git/uv/nuwaxcode 等运行资源；先在各自源码仓升级、跑对应门禁，再更新外层 gitlink。
- 基座使用 pnpm 9.15.5，前端与外层声明 pnpm 10.27.0；不要用外层版本覆写基座锁文件。依赖安全告警按影响产品、可利用面和可升级版本记录处理结果。
- 发布 tag 的 gitlink 是源码事实源。`release-provenance.json` 和五平台 `build-manifest-*.json` 是安装包来源证据；源码提交、构建、同步、安装验收分别记录。

## 本地诊断

在故障机器上的本仓检出运行 `npm run diagnostics:export -- --output ./nuwax-diagnostics.json`。脚本读取 `~/.nuwax/logs` 最近三份按日日志的尾部样本，只输出级别、白名单组件及少量系统错误码计数；不复制日志正文，也不读取数据库、cookie 或配置。固定端口探测只表示“有进程监听”，不能证明进程归属和健康。输出文件在 POSIX 系统上按 `0600` 创建，由维护人员按工单需要主动提供。

## 发布与回退

- beta 和 stable 指针只有在五平台来源、签名及版本目录上传校验通过后推进；指针发布步骤失败会尝试恢复先前对象，并以红灯报告。跨存储服务无法保证原子更新，失败后仍须分别核对 S3 与 OSS 的当前版本。Windows MSI 当前未签名，不写入自动更新指针。
- 已发布版本回退时，先确认目标 tag 资产仍在版本目录且签名有效，再通过独立同步 workflow 指向目标 tag，并记录变更前后指针及真实旧客户端更新行为。不要重写既有 tag 或用新内容覆盖同名安装包。
