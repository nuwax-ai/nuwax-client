## 实施顺序

1. 只在 overlay 安装器文件接管进程关闭逻辑，保留当前仓库及 submodule 既有改动。
2. 检查宏与 electron-builder 25.1.8 模板的插入顺序及 per-user/per-machine 过滤行为。
3. 后续在 Windows 交互式桌面构建/安装包验证 W1-W6；没有真机证据前不宣称安装验收通过。

## 证明成立的测试

- 2026-09-23 的进程关闭实现未记录真实安装验收；2026-10-21 续作的源码与原生夹具结果见文末记录入口。
- 待验收：Windows NSIS assisted 安装包覆盖安装及上述 W1-W6；需在已登录的 Windows 桌面会话验证。

## 风险与回退

| 风险 | 缓解 | 回退方式 |
|---|---|---|
| 权限高于安装器的进程无法被结束 | 保留重试/取消提示和手动关闭路径 | 回退 overlay 宏，由 electron-builder 默认检查接管 |
| 强制结束会中断未完成的会话任务 | 先请求正常退出并等待 10 秒，仅超时后强杀 | 回退 overlay 宏 |
| NSIS 宏编译或进程过滤语法与预期不符 | Windows 包构建和真实交互安装作为后续验收门 | 在 Windows 验收后再进入发布链 |

## 偏离记录

- 当前实现沿用 NSIS 原有权限模型，不增加 UAC 提权强杀；按本次接手时确定的范围执行。

## 2026-10-21：3.0 安装恢复续作

- 基线：`release/v3.0`，初始 `470a5373`，隔离分支 `fix/windows-installer-recovery`；保留主工作区与其他任务修改。
- 3.0 已包含卸载性能、备份保留、自定义路径及任务栏图标修复（`1a6d6279`、`934f280e`），不重复合并历史任务。只回迁 3.1 的孤立私有路径登记修复（`39f4c3f1e`）。本分支已快进跟随 `a34ec02a`，保留基座 `d12d001a` 与两个前端 pin。
- 本轮扩大现行契约第 5 节：事务重试、失效指针归档、完整包维护、旧卸载器失败接管、登记快照、路径校验及精确快捷方式/启动项清理。恢复状态由 PowerShell 统一维护，NSIS 负责界面与编排，不改 vendor 模板。
- 原生交互验证补齐路径与范围边界：拒绝已有安装的意外目录迁移；重申显式范围；all-users 操作保留其他 per-user 副本及其损坏时的别名；共同目录双重登记与无选择的静默并存调用停止。并存副本夹具见 `scripts/test-installer-scope-isolation.ps1`。
- 更新模式也只删除卸载器自身清单，不再递归移除安装目录；先核验已完成的保全事务，不提前恢复父安装器暂存文件。缺失卸载器、占用重试及更新模式未知工作区保留由原生卸载夹具验证。初版已合入 3.0，后续保护经 PR #49 回流；版本与打包由已有发布任务统一安排，修复任务不另编版本。
- 原生默认别名回归发现 vendor 在精确清理后仍按名称删除链接；商业 hook 停用该后置清理，更新保留别名，修复恢复被模板重写的其他副本链接，并直接启动所选程序。相同原生场景先复现失败，再验证修复及两个安装范围，保留默认保留数据与删除数据界面验证。
- 源码与夹具检查结果见 `docs/acceptance/20261021-windows-installer-recovery-source-verification.json`；Windows 原生 NSIS 的随机 QA 身份和合成载荷验证与真实商业包验收分开。用户操作方案见现行契约第 6 节。
- 先经 PR 回流 `release/v3.0`，再独立同步到 `release/v3.1`，不引入整条 3.1。签名商业包与真实旧版本安装验收通过后才进入发布，不改写历史 tag 和产物。
