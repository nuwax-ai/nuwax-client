## 2694：优先命中与抢占调查

用户后续指定先调查抢占，不采用更换默认键方案。默认截图键与用户自定义组合均保持原值；本项尚未修复，不回写禅道解决状态。

| 方案 | 能力与边界 | 下一步 |
| --- | --- | --- |
| Electron `globalShortcut` | 没有优先级或独占参数，`isRegistered` 只描述当前应用；macOS 可接受两个进程同组合注册 | 无法靠重复注册、应用内防抖或提前启动可靠抢占飞书 |
| macOS Carbon `kEventHotKeyExclusive` | Apple SDK 声明可抑制非独占注册的热键通知，不需要新增辅助功能权限；已有其他独占注册时不能强抢。Electron 维护者指出效果随系统版本、另一应用的请求方式及顺序变化 | 候选一：用原生注册与回调替换截图域的 Electron 注册，先做双向启动顺序与真实飞书按键验证；注册成功不等于飞书没触发 |
| macOS 主动 `CGEventTap` | 可以删除匹配按键事件，需要系统相应输入/辅助功能授权；被动监听不能吞键。不能承诺压过其他位置、更早收到事件的拦截器 | 候选二：独占注册不足时再验证；需独立事件线程、极短回调、权限失效与退出释放，不在 JS 回调中执行截屏 |
| Windows 原生热键 / 键盘钩子 | `RegisterHotKey` 通常拒绝已被注册的组合，不能强抢其他应用；`WH_KEYBOARD_LL` 返回非零可阻止后续钩子及目标窗口接收事件，但要维护消息循环并避免超时被系统移除 | 候选二同上；必须验证飞书的实际触发链，不将通用低级钩子的能力当作兼容性保证 |

本机 macOS **27.0.1** 原生双进程注册实验使用不常用的 `Ctrl+Command+Option+Shift+F19`，不发送物理或合成按键，不更改系统权限。普通→普通、独占→普通、普通→独占均返回成功；独占→独占第二个进程返回 `-9878`。只证明注册结果，未验证按键触发优先级，更没有证明飞书共存通过。两个进程自行注销并退出。源码与记录见证据目录 `hotkey-priority-probe.m`、`hotkey-priority-probe.json`。

- [Electron 维护者对 macOS 独占注册矩阵的说明](https://github.com/electron/electron/issues/53770#issuecomment-5613616812)；报告针对 42.8.0，不能据此宣称当前 40.8.2 已验证。
- 本机 Apple SDK `CarbonEvents.h:15394`–`15476` 的 `kEventHotKeyExclusive` / `RegisterEventHotKey` 文档。
- [Apple CGEventTapCallBack](https://developer.apple.com/documentation/coregraphics/cgeventtapcallback) 与 [tapCreate](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:))。
