# 老账号可选用户名与登录入口修复

- 登录身份依据后端验证通过的 Cookie 会话及稳定账号 ID；用户名不再是必填字段。
- 展示名称依次使用非空用户名、昵称、未知；展示名称不参与账号切换判断。
- 会话同步与设备注册共用账号解析，保留旧接口仅返回用户名时的兼容性。注册字段仍使用真实用户名/手机/邮箱，昵称和“未知”不作为登录凭据。
- 持久化稳定账号标识，并与 savedKey 成对保留或清除；IM 使用同一稳定标识隔离账号。
- 客户端 tab 的“去登录”先关闭设置弹窗，再切回业务 WebView。
- 在隔离目录同步商业 overlay，先复现旧账号失败，再验证登录、注册、同名账号切换、昵称变更及拒绝无效会话。保留当前基座未提交差异，只同步本次改动。
- 登录后导航保持原有密码/验证码共享历史条目的流程；补充老账号重复恢复会话及注册失败不清登录的回归。
- 验证：新增测试先复现 7 项失败；修复后，当前基座差异集的商业认证/Cookie/IM 链路 189 项通过，前端认证与导航 88 项通过。主进程生产构建、壳 renderer 构建和差异检查通过。
- 后端响应复查：同一账号当前已经返回非空用户名。本次仅做只读查询，未修改后端账号数据；空用户名场景由隔离回归验证，不能用最新响应宣称真实空用户名安装包验收完成。
- 状态：首批登录修复已以 f0e00f9 合入并推送 release/v3.0.x；本次改动定点同步到当前基座，保留原有未提交差异。开发客户端已启动并使用独立测试数据目录；未打包发布或替换当前安装版，真实安装包验收仍需单独完成。

## NUW-49：企业登录切换域名

- 根因：SPA 登出后主进程更新会话代次，但登录页仍使用原文档；直接调用切域接口被文档代次校验拒绝。
- 修复：guest preload 的显式切域操作先调用 auth:getContext，成功后才调用 auth:configureServerHost；主进程保持旧文档与来源校验。
- 回归：直连登出后切域、其他旧文档仍拒绝、迟到登出不授权旧文档、直连/网关 preload 调用顺序、不可信上下文拒绝。
- 修正账号展示改动中混用的 ID：auth.user_info.id 保持设备注册配置 ID，auth.account_id 存稳定账号 ID；重复会话同步保留同域注册 ID。
- 安装版复现：macOS /Applications/Nuwax.app 3.0.10，直连模式，在同一文档调用实际 auth.clear 后企业登录切域出现 Stale document；通过实际桥读取当前上下文后，再点击切换正常重载到目标域名。此诊断验证修复路径，尚不等同于新构建验收。
- 隔离商业测试：源码 overlay 132 项通过；保留当前基座差异的认证/Cookie/IM/电脑状态/preload 集成 218 项通过；主进程构建与 diff --check 通过。
- 密码登录另有独立阻塞：正式客户端实际 passwordLogin 请求 HTTP 200，code 0001，message 校验参数异常；脱敏检查确认账号、密码匹配输入，验证码参数含 sceneId/certifyId/deviceToken/data，重新初始化后仍失败。应继续按用户提供的测试 API 文档核对，未判定登录成功。
- 接口文档复核：测试站 OpenAPI 的 PasswordLoginDto 同时列出 phone 与 phoneOrEmail，phone 描述为带区号手机号，phoneOrEmail 描述为邮箱；实际客户端发送 phoneOrEmail。此差异尚不能证明当前错误根因，已检出的后端实现兼容 phoneOrEmail，错误消息来自验证码校验。公开租户配置只读核对：正式站 openCaptcha=1、openImageCaptcha=0；测试站两者均为 0。测试站关闭验证码时的登录结果不能覆盖正式站验证码验收；没有修改账号字段或验证码配置来绕过校验。
- 按用户最新要求停止追加人工客户端验收，由用户验证。临时隔离副本启动失败，未作为新构建验收；临时副本与其独立数据目录已清理，原安装版未替换。

## 应用登录新窗口未继承平台会话

- 客户端复现：已登录测试平台，点击新闻应用预览的登录按钮，新窗口先经过应用登录路由，再跳平台 /api/oauth2/authorize，最终显示平台 /login；登录页 redirect 指向 OAuth 授权接口。浏览器正常这一差异由用户提供。
- 根因：sessionAuthInjection.ts 把来自应用域的顶层 OAuth 授权跳转按普通跨域 API 请求处理，去掉 Chromium 已选中的平台 ticket Cookie。
- 修复：顶层 GET 导航按当前配置业务域匹配，保留 Chromium 已选中的平台 Cookie，不绑定固定域名或授权路径；来源匹配包含协议和端口。外域 XHR、子框架、WebSocket、POST、公开登录接口和第三方回调继续按原规则隔离凭据。
- 回归：修复前新增场景 4 项失败、52 项通过；修复后 Cookie/弹窗/网关 4 个文件、160 项全部通过，开发主进程编译成功。
- 实测：重启开发客户端并保留原测试数据，打开同一新闻应用、点击同一登录按钮，新窗口完成授权后回到新闻站，显示当前用户和退出登录按钮。用户确认成功。
- 用户补充要求不固定地址，只按当前域名匹配：移除首版授权端点例外，复用主进程动态业务来源；新增自定义企业域名、其他 API 路径、切域后新域生效与旧域失效的回归。更新规则前 5 项失败；更新后 Cookie/弹窗/网关 4 个文件、170 项通过。
- CAS 退出后免密登录已由用户说明为已知情况，暂不处理；相关探索代码已撤回，未纳入 release。
