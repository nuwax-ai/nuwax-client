# Dev 更新通道实施计划

- 状态：实现完成；2026-11-05 用户确认方案并授权实施、创建 PR。后续按用户要求停止追加测试。
- 范围：客户端三级订阅及发布分发，不触发实际发布。
- 已定边界：Dev 对应 `alpha.N`；Stable/Beta/Dev 分别接收 Stable、Beta+Stable、仅 Dev。用户补充确认 Dev 更新频率较低，固定订阅以保留 Dev 新功能体验。关闭 Beta 同时退出 Dev，再开启不恢复 Dev。不自动降级。
- 初始化：保持现有 Stable/Beta 初始化和已有选择；首次安装 Dev 包默认 Stable，用户显式逐级开启。Dev 暂无更新入口或网络/校验失败时保持 Dev 订阅，不回退 Beta。
- 发布：Dev 使用现有预发布构建矩阵、源码 pin、签名和来源校验，独立 `dev-build/<tag>` 与 `dev/latest.json`。Beta/Stable 不推进 Dev 指针。Stable 转正关闭同号预发布序列，Dev/Beta 序号各自递增。

## 步骤

1. 共享通道契约、设置联动和国际化；主进程验证订阅值并继承 Beta 的调试行为。
2. 更新器按通道限制候选，处理切换时的在途结果与下载/安装目标，并阻止退出时安装已排除版本。
3. 扩展发布身份、版本序列、来源验证、同步路径及三通道指针事务；复用现有预发布 workflow。
4. 增补设置、更新器和发布脚本的行为测试，运行定向测试、类型检查及 workflow 校验；记录实包验收边界。

## 验证重点

- Stable/Beta 不接收 Dev；Dev 不受更高 Beta/Stable 影响，关闭后回 Beta；跨基础版本优先比较基础版本。
- 双开关仅三个有效状态，持久化失败不假成功；已有选择跨安装保留。
- 切换时旧响应不能覆盖新候选，已下载旧包不能自动安装或退出安装；下载/安装期间暂不可切换。
- Dev 发布只动 Dev 指针；成熟版本只在更高时传播；错误/镜像不一致可回滚。
- 不改动现有 ACP WIP、前端子模块或 agent-platform，不创建发布 tag/Release。
