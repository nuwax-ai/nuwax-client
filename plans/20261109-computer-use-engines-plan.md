# Computer Use 可选执行引擎

## 已确认范围

- 在客户端 Computer Use 设置中增加执行引擎下拉：CUA Driver（缺省）和 Agent Desktop（实验性），按本机持久化。
- 共用宿主会话授权、窗口范围、黑名单、敏感操作确认、观察预算、暂停/停止/接管和错误恢复。
- 活跃任务和配置操作期间禁止切换；切换时撤销旧连接和快照，不自动降级或重放未确认的写操作。
- 现有 CUA 路径保持默认；Agent Desktop 用明确限定的原生操作集合接入，不将它的完整 MCP 权限直接交给模型。

## 实施

1. 增加引擎标识、能力状态、受信 IPC、preload API 与四语言设置入口。
2. 为 Agent Desktop 实现独立执行适配器，规范工具参数、观察引用与结果语义，复用现有网关和控制器。
3. 按固定版本准备引擎资源，隔离开发/生产数据目录，保留来源与完整性证据；不改变 CUA 原生缓存配方。
4. 验证引擎选择持久化、忙碌拒绝、会话/目标越界、过期引用、撤销和迟到结果、未知写入结果不重放；验证构建。

## 验收边界

- 源码测试/构建通过不等于三平台安装包验收。
- 对尚未实现的原生能力明确返回不支持，不将进程退出或接口成功伪装成操作成功。
- 当前工作区有独立的媒体权限和开发工具链修改，仅增量修改本需求涉及代码，保留无关 WIP。

## 完成与验证

- 已完成本机引擎选择、忙碌拒绝、受信 IPC/preload、四语言 UI、资源准备/打包和独立许可证准入；未改变 CUA/capture 的原生缓存配方。
- Agent Desktop 通过内部 RPC 适配器复用网关；只开放已适配的无障碍工具，不导出任意命令、输出路径、浏览器或物理输入能力。停止后清理连接快照，重启后可重新探测权限。
- Computer Use 全域测试、宿主端口测试、资源/准备/打包/许可证定向测试通过；主进程类型检查、导入边界、main/preload 和 renderer 构建通过。
- macOS 临时原生应用实测通过：读取、设置文本、点击后观察实际效果、过期引用拒绝、停止后拒绝调用。测试程序已清理。
- 原开发工作区存在主题接口与壳快照差异；独立检出固定前端 pin 后，`host-bridge:check` 已通过，未携入主题、媒体权限或其他前端 WIP。
