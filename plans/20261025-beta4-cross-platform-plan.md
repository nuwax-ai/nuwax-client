# Beta.4 跨平台代码门禁与发布

用户最新授权（2026-10-26）：客户端合并到 `release/v3.0.23` 后发布 Beta；PC Web 合入 `feat-2026.9.30`，测试环境由用户部署。Windows 剩余实机验收仍由用户补；先保证候选代码具备多平台能力和正确性。覆盖此前“客户端 PR 不合并”要求。独立验证系列的4/4历史保留，不再触发验证构建；本轮仅在代码门禁通过并合并后创建一个正式 Beta tag。

1. 走查整个待发布批次的内聚、分层、维护性，重点核对本机文件路径/原子写入/回收站、CU偏好/平台权限/目标与token适配。保留未涉及的工作区改动和双 pin。
2. 在现有 CI 补 macOS、Windows、Linux 的本机文件与 CU 分域测试。运行真实宿主平台的 Node 文件系统用例，不以修改 process.platform 的模拟代替；确认平台差异造成的失败后，窄修复实现或纠正不成立的平台测试假设，不跳过整个功能域。
3. 现有社区、商业、前端、终端门禁和新增三平台门禁全部通过；复核 overlay/pin/契约，完成代码质量结论后准备 v3.0.23-beta.4 说明与正式预检。若远端已使用该版本，则重新核对版本序列，不覆盖旧 tag。
4. 门禁通过后合并 #66 到 `release/v3.0.23`，在合并提交走正式 Beta 五平台工作流，源码和前端 pin 冻结，核对签名/来源清单/资产哈希/公开 Beta 指针。正式 Beta 按原策略从源码 pin 生成一次共享前端，不能声称其字节与此前 dist 验证包完全相同。
5. 清晰交接 Windows EXE 下载入口、升级开关与 Claude 实际任务、文件操作和控制矩阵；记录已知 Windows ARM 第三方 Nuwaxcode 崩溃未修，不把用户承担实机验收写成已通过。
