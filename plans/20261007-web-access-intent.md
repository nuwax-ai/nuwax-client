# 意图：任意网站正常访问，业务页面共享登录

- 日期：2026-10-07
- 来源：ZCode `sess_7142143c-3e46-41a8-bbd1-b4d07450801e` 今日 16:01 用户需求，以及本会话接手处理指令。
- 状态：访问范围已由用户明确；沿用现有业务凭据边界实施。

## 问题

商业客户端按照目标域名把跳转搬到临时窗口，第三方窗口使用一次性会话。业务页面存在第三方 iframe 或从业务镜像域发起弹窗时，站内链接也可能丢失登录。今天 beta 构建还因生产 prebuild 自动追微应用远端而无法收敛。

## 预期结果

- 任意 HTTP/HTTPS 域名可在原窗口导航、重定向、新窗口或 iframe 中加载。
- 配置业务源、启用的 loopback 和开发覆盖源之间的业务页面，使用共享会话；不因不相关第三方 iframe 存在而丢失站内 GET 链接登录。
- 第三方正常保留自身 Cookie；业务 ticket、网关私有能力及宿主桥仍按实际目标/文档/请求 frame 校验。
- 构建只消费记录的源码与微应用 pin，显式升级负责改变 pin。

## 受影响的能力面

商业主窗口 guest、新窗口策略、native.openWindow、请求鉴权、轻量 preload 和微应用构建入口。社区行为保持既有默认。

## 约束

- 不把任意域加入业务源集合，不把企业切换前的旧域或所有子域视为当前登录源。
- 仅处理 HTTP/HTTPS 普通网页，不扩展 file/javascript/custom scheme。
- 不取消同源策略、sandbox 或上下文隔离；iframe 解除已有 XFO/frame-ancestors 机制继续生效。
- 不保证绕过父页面其余 CSP、混合内容或网站脚本自己的限制。
- 不覆盖现有未提交工作；保留主检出的前端偏移，使用独立前端检出构建。

## 开放问题

- 用户可在本会话纠正第三方桥/登录能力边界；默认沿用现有边界，不扩大凭据发放范围。
- 今天 ZCode 使用的 beta 3.0.4 已可能落后于版本线；发版前以当前远端 tag 检查确定新版本，禁止覆写旧 tag。
