# Windows 首装耗时与卸载后续修正

## 范围和约束

承接 NUW-21 / BUG-31，2026-10-08 用户要求先建任务卡并着手处理。随后明确已集成资源是原定要求，先核对哪些资源没有需要，不能直接删减既有集成能力。

- NUW-40：审计每项资源用途、运行入口、原定集成/离线要求和重复/缓存候选；不直接删除资源。
- NUW-41：完整资源载荷下的安装写盘优化。先提供显式启用的 ZIP QA 候选，默认正式包仍使用原有 7z 路径。
- NUW-42：先修复 Restore 冲突后提前完成和清 marker 的状态错误，保留数据和重试路径；独立卸载修正需要 Windows fixture 证据。
- NUW-43：同一真实 Windows 设备对比阶段耗时、安装失败恢复、卸载、签名和更新行为。
- NUW-44：提前准备五平台 3.0.9 Beta 验收候选（Windows x64、macOS arm64/x64、Linux x64/arm64），供 2026-10-09 用户真机验收。

## 实施

1. 保存独立 worktree 当前基线与拟改文件；原工作区、脏子模块和历史 QA 包保留。
2. 并行审计资源用途与原需求。按“确认必需、重复/缓存候选、用途待确认”记录；没有静态调用不能作为删除证据。
3. 抽出安装归档策略供本地 pack 与 legacy build wrapper 使用；显式 QA 模式才同时设置 `differentialPackage: false` 与 `useZip: true`，普通构建和资源选取不变。校验平台、版本和参数冲突，私有选项只支持已核对的 builder 25.1.8。
4. 修复恢复冲突状态：只有零冲突才写 `restore-complete` 并清 marker；有冲突写未完成状态，下一次 Prepare 拒绝混入新恢复，用户数据继续保留。
5. ZIP 候选和卸载后续变更通过真实 Windows 失败/中断场景之前，不进入默认正式策略。

## 验证与交付

- 配置和调用路径测试：默认 7z 不变；显式 ZIP 两个布尔值成对设置；本地和 legacy 入口一致；所有 `extraResources`、签名/版本/发布字段保持。
- 使用实际 electron-builder 25.1.8 schema/模板核对 ZIP 格式选择与定义；不把 stub 测试当 Windows 安装结果。
- 恢复 Windows fixture：发生 Restore 冲突时 marker/manifest/数据哈希保持；再次 Prepare 拒绝；解除 fixture 冲突后 Restore 能完成。
- 运行对应脚本回归、overlay 同步/检查与 pin 检查；交付精确补丁、资源审计及结果/未测项目。
- 用户已明确要求提前打包：仅推送冻结候选及已自测前端到隔离 QA 分支，复用五平台 CI。QA 构建只上传验收资产，记录精确源码和哈希，不创建正式发布 tag、不移动公开 beta 指针。
- 不操作真实用户机器卸载、清数据或按通用进程名称终止未知进程。

## 当前限制

本机是 macOS；没有确认本次可用的 Windows 交互设备。源码/配置/夹具脚本不能证明 Windows 安装已经提速或原卸载错误已经解决。Windows 对照由 NUW-43 承接。

## 资源审计结论

19 项资源经用途和原需求核对，当前完整保留。Windows 停止/清理会加载 agent-gui-server 的管理库，不能因为旧 GUI 功能关闭就删除整树。跨平台二进制池、准备归档和 dev-only 工具等是后续局部候选，尚未经真实运行验证，不在本候选中移除。
