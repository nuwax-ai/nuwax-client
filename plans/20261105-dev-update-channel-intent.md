# 意图：为客户端增加逐级主动开启、固定订阅的 Dev 更新通道

- 日期：2026-11-05
- 状态：已接受；用户确认实施，并补充确认 Dev 低频发布、开启后固定体验 Dev，关闭后返回正常 Beta 测试通道。

## 背景和目标

Beta 用作频繁发布的测试通道；Dev 发布较少，但可能提供独有的新功能体验。开启 Dev 的用户应持续跟随 Dev 最新版，避免被更高、更频繁的 Beta 覆盖。

## 用户与订阅流程

| Beta 开关 | Dev 开关 | 当前订阅 | 可接收发布 |
| --- | --- | --- | --- |
| 关 | 隐藏且关闭 | Stable | Stable |
| 开 | 关 | Beta | Beta、Stable |
| 开 | 开 | Dev | 仅 Dev |

- Dev 只有在 Beta 开启后才显示，默认关闭，开启须用户确认。
- 关闭 Dev 回 Beta；关闭 Beta 同时退出并隐藏 Dev。重新开启 Beta 不恢复 Dev。
- 单一 `stable | beta | dev` 设置表达三个有效状态，选择跨重启、安装更新和转正保留。
- 已有 Stable/Beta 初始化保持兼容；Dev 包首次安装不自动开通 Dev，用户须显式选择。

## 版本与切换

- 用户开通顺序 Stable → Beta → Dev；同基础版本内的版本优先级 Dev < Beta < Stable。
- Dev 使用 `X.Y.Z-alpha.N`，Beta 使用 `X.Y.Z-beta.N`，保证所有更新组件的排序一致。
- 先比较基础版本，再比较阶段和序号；Dev/Beta 序号分别递增。
- 固定订阅 Dev，不因 Beta/Stable 的频率或更高版本切换通道；Dev 没有新版本时停留当前安装版本。
- 切换只改变后续订阅，不自动降级。若目标通道最新版低于当前安装版本，等待目标通道追上。
- 在途检查按当前订阅重新获取候选；切换后清除已下载候选和退出安装标记，避免安装旧通道包。
- 下载/安装过程中暂不可切换，保持 feed 与目标一致。

## 发布分发

- Dev 独立使用 `dev/latest.json` 和 `dev-build/<tag>/`，Dev 发布只推进 Dev 入口。
- Beta 发布只推进 Beta；Stable 推进 Stable，并在版本更高时推进 Beta。两者不推进 Dev。
- 独立 Dev 入口未建立、网络失败或元数据错误时保留订阅，不回退到 Beta。
- Dev 复用预发布五平台构建、固定源码 pin、签名、公证、来源和哈希验证。
- Stable 转正后关闭同基础版本的预发布序列；不移动既有 tag，不替换同版本来源。

## 本期范围与约束

设置联动与国际化、订阅持久化、候选限制、版本排序、切换一致性、Dev 发布与分发、既有 Stable/Beta 兼容。
不包含白名单、灰度比例、强制降级、独立产品/数据目录或自动回滚。
实际打包、发布和安装包平台验收另行执行；本次实施不触发发布。

## 验收观察点

- Stable/Beta 用户不会收到 Dev；Dev 用户不会被频繁发布的 Beta/Stable 覆盖。
- Dev→Beta/Stable 只在用户关闭对应开关后发生，目标不更高时不降级。
- 三种设置状态一致，持久化失败不显示成功，既有选择不因升级被覆盖。
- 切换后的状态和安装目标均来自当前订阅；下载/安装期间切换被拒绝。
- Dev 指针独立推进，错误及镜像不一致会阻止发布，部分写入失败回滚。
