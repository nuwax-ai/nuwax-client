# 意图：Nuwax 客户端原生截屏 / 录屏能力

- 日期：2026-10-12
- 来源：用户报告「IM 输入框『截取屏幕 / 窗口』在桌面客户端 v3.0.13 点击无反应」，并要求客户端提供原生底层能力（截屏、录屏→视频文件 / GIF、可选压缩档且尺寸不变、HDR 屏处理），做成相对独立的特性模块，并在「关于」页展示开源组件声明。
- 已通过会话中的需求访谈确认，不再要求用户重复确认。

## 问题与预期结果

根因（源码确认，未在 v3.0.13 实机复现）：主进程没有 `session.setDisplayMediaRequestHandler`，权限白名单无显示捕获，页面 `getDisplayMedia()` 被宿主拒绝；IM 又把失败静默吞掉，所以点击无任何反馈。

预期：IM 通过宿主桥调用客户端原生能力完成截图与录屏；所有交互界面（选区、标注、录制控制条）由客户端原生窗口提供；失败有明确错误码。

## 范围与约束

- 商业 overlay 内的独立特性模块，社区基座不受影响；既有代码只做少量通用接缝改动。
- v1 交互：整屏/窗口选择、区域框选、标注工具、录制控制条；不含音频、跨屏选区、窗口悬停高亮、Linux。
- 产出：静态图；视频 mp4 与 webm（调用方选）；GIF。压缩只降质量、像素尺寸不变，分档由调用方决策；HDR 屏一律输出 SDR/sRGB。
- IM 不由本仓修改，交付接入文档 `docs/native-capture-api.md`。
- 「关于」页新增「开源组件声明」（对标微信、飞书），并作为 ffmpeg 入包的前置闸门。
- 全部在 nuwax-client 内实现（overlay、商业 `scripts/`、`third-party/`），**不修改基座仓** `nuwa-electron-shell`；开源组件声明仅商业版有入口。
- 产品决策已定；技术未知项（HDR 采集成像、ffmpeg 构建、窗口录制排除控制条等）由 Phase 0 真机验证。
