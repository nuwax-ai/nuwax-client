# 定制浏览器页签与支付窗口

## 已确认规则

- 只有支付场景独立开新窗口，仍使用同一套定制浏览器样式；支付子流程继续留在独立窗口链路。
- 普通外链、当前业务域链接和旧业务开窗调用共用一个浏览器窗口，每次打开一个新页签。窗口关闭后再次打开时重新创建。
- 各页签独立保存网页、前进后退、查找、地址展开和加载失败状态；复制、刷新、缩放和打印作用于当前页签，置顶属于窗口。
- 支付沿用现有 `purpose: payment` 标记及其子窗口继承，不按域名猜测用途。现有支付入口已传此标记；旧的普通 `native.openWindow` 调用不再因为未标记用途而使用旧窗口外观。
- 保留当前登录会话、Chromium 原始 guest/opener/POST、支付回调与 beforeunload。关闭页签、下载空页清理和请求方退出不得误关其他页签。
- 业务来源、Cookie 过滤、桥权限和登录失效撤销仍由宿主校验。显式选择系统浏览器的普通外链继续遵循用户设置；需业务登录和支付的页面留在应用内。

## 实现与验收

1. 浏览器特性分别管理窗口和页面，普通页面复用窗口、支付页面隔离；工具栏 IPC 仅可操作所属窗口内页签。
2. 顶栏增加页签切换和关闭，复用现有标题胶囊与操作区；关闭最后一页后关闭该窗口。
3. 统一 window.open 和 native.openWindow 的内置承载；下载及 opener 生命周期改为页面级清理。
4. 定向单测和真实 Electron 验证同/异域页签复用、历史和查找隔离、关闭/下载不误关、支付窗口/POST/opener/回调以及 CSP 和原有复制 toast。

Beta.24 已冻结并独立构建。本次重构先在 Dev 验证并提 PR，不移动现有标签或自动重打 Beta.24。

## 完成情况

- 已实现普通页面共窗新页签、支付独立窗口；历史业务链接及当前域名的 IM 链接统一使用定制顶栏。
- 按用户追加意见，非当前页签最大 160px、最小 64px；当前页签 180–220px。数量多时压缩为图标，极多时横向滚动，暂不增加折叠菜单。
- 关闭按钮平时隐藏，hover 或键盘聚焦页签时替换左侧图标；停止加载用方块图标，避免两个叉号混淆。
- 页签收窄为图标时图标与关闭按钮都居中，保持原位切换；当前页签按微信参考图突出选中背景，刷新入口在 hover/聚焦或加载中显示，按钮有 hover/按下反馈，前进后退使用折线箭头。
- 关闭按钮使用与刷新/更多一致的 30px 点击区、19px 图标；图形按视觉面积放大。浏览器通过通用宿主窗口接口读取实际主题，遵循客户端暗黑功能开关、用户设置和系统模式，不再自行决定深浅色。
- 定向单测 212 项通过；主进程类型检查、renderer 构建和 import boundary 检查通过。严格特性边界门禁被主线 PR #116 引入的 capture → shared/utils/fileTimestamp 导入拦住，已在 PR 记录；浏览器本批次没有新增该类违规。
- 真实 Electron 自动回归覆盖同/异源页签复用、鼠标切换关闭、长标题与十页签窄屏布局、历史/查找隔离、beforeunload、下载页面级清理及支付的 POST、Cookie、opener、回调和 window.close。支付使用本地模拟页，不代表真实支付渠道验收。
- Dev 已重启加载本分支主进程，实际客户端观察到同一浏览器窗口的两个页签，供用户继续验收；不改已安装 Beta。
