# 实施计划：Computer Use 产品运行闭环

- 对应 spec：`specs/computer-use-product.md`
- 状态：已接受（2026-10-13 用户要求实现）；当前会话 Default 模式，落盘同等计划工件后实施。

## 2026-10-21 Codex 风格悬浮预览（当前优先，实现候选）

- 用户调整顺序：先解决悬浮小窗口的 UI 交互，再继续双平台基准与失败优化。模型运行已结束或撤权排空，本地桥接/隧道和本地 VM 测试计划任务已清理，已有结果保留；未连接同事电脑。
- 主页面取消重复的多任务悬浮管理面板，统一使用宿主预览，设置页继续提供任务管理和恢复。按用户参考图移除预览外围标题栏和大面板：目标窗口画面直接悬浮，其他任务向左下错位叠放；关闭/接管位于画面外侧上方，悬停或键盘聚焦显示控制。任务身份与暂停状态使用轻量胶囊，窗口绑定/模式切换收进任务菜单的折叠设置。
- 默认 420×320，用户已有尺寸偏好保留；收起后为 42px 控制胶囊，点击任务名或展开按钮可恢复。关闭仍只收起，停止当前任务和全部急停保留独立入口。悬浮显示仍不激活目标应用，预览和写权限分离。
- 已通过真实 Electron 交互夹具、49 项相关商业测试、主进程及 renderer 构建；覆盖明暗主题、多任务、键盘显示控制、收起记忆、胶囊展开、接管等待与完成清帧。视觉截图为合成任务 UI 夹具，不能替代真实安装包或 Windows 原生外观验收，详见现有验收记录。

## 2026-10-21 真实模型任务基准与可靠性优化（已接受，实施中）

- 验收口径补充计划 `20261021-computer-use-acceptance-supplement.md` 已由罗东拍板（全部按建议值）：主力模型 glm-5.3-flash；办公统一 LibreOffice（原生办公单列回归）；X 类跨应用推迟到第三阶段（当前 22 条口径，X 类达标后并入 26 条）；S 类系统设置需显式前台模式并单独统计；Linux 不纳入发版门槛（只做 OSWorld 子集探索）；同事电脑（Win235）排除，Windows 仅本地 ARM 虚拟机；OSWorld 以 `~/workspace/OSWorld` 为基线，分层随机+固定种子、排除外网账号任务，平台适配先做 Linux X11 子集。

- 用户确认实施顺序：先跑 macOS / Windows 真实模型任务基准和验收，再按失败原因逐项优化，最后扩展长流程和效率；保留现有多窗口与预览 WIP、发布线和子模块 pin。本阶段不接 Nuwa Browser、不发布版本。
- 设备边界：不使用同事的 Windows 电脑调试或验收，也不再连接该设备收集结果；后续 Windows 验证限定本地虚拟机。此前误用该设备产生的结果撤出验收证据和优化依据，不能作为 Windows 已通过的证明。
- 复用现有 Rust helper、窗口任务注册表、会话授权、MCP 网关及 Agent 接口。原固定规则基准继续作为控制层回归；真实模型运行与夹具自测、第三方应用、正式签名安装包验收分别标识，禁止互相替代。
- 第一阶段：建立可重复任务目录、隔离初始状态与独立结果校验器。首批打通两平台的文本输入/修改、元素选择、滚动、动态 UI 和原生编辑器任务，再扩展到每平台 50 个核心任务、20 个异常场景，每项 5 次。模型只可通过受控窗口工具执行；评测准备和校验能力不暴露给模型。
- 指标：无人接管成功率、人工辅助成功率、首次定位/动作效果、观察与写动作数、耗时 P50/P95、恢复次数、模型 token、每成功任务成本（含失败重试）。未提供 token/价格时标为未知，不能按零计算；模型自报完成与工具派发成功不构成业务成功。
- 固定任务版本、初始状态、平台/应用/模型版本、代码及 WIP 指纹、输入模态、前后台模式、工具许可与预算。首轮、优化后及留出任务分别比较；环境阻断和不支持任务也计入覆盖报告，不能静默剔除。核心任务无人接管成功率 ≥90% 为内部建议目标，不能据此直接宣称行业第一梯队。
- 第二阶段：按基线失败占比优化目标定位/过期引用、动作后结果核验、加载等待与有界恢复；不确定写入先核验，禁止盲目重放。第三阶段再处理受控关联弹窗/跨窗口长流程和成本，任何新增窗口授权需先更新现行契约。
- 控制正确性为硬门槛：错窗写入、撤权后执行、未授权扩大范围立即判失败并阻断交付。浏览器 GUI 与 DOM/CDP 分轨统计；预览画面仍不作为模型观察、轨迹日志或持久化证据。
- 双平台执行记录保存非敏感任务结果及失败分类，不保存密钥、普通用户截图或窗口内容。真实应用、物理输入互不干扰、多屏/DPI、锁屏/权限撤销、签名安装包和八小时稳定性继续按已有验收清单逐项完成。
- 当前进度和命令更新在 `docs/acceptance/20261019-computer-use-multiwindow.md`，本节持续更新状态，不另建实施计划。
- 已落地 `scripts/computer-use/bench/real-run.mjs`：7 项试点、真实随包 ACP Agent、独立业务 oracle、合成图片预检、受限工具、原子结果报告、usage 计数及取消/排空清理。新增命令说明见该目录 README；所有原有 WIP 和 pin 保留。
- 首轮证据：Mac 6 项 GUI 夹具全失败。定位到 helper 的 `snapshot_id` 只在 `structuredContent`，Agent 只将 MCP 文本/图片交给模型。宿主现把原始快照 ID 同步到模型文本通道，仍由原生检查引用有效性，未修改写入权限。
- 修复后的第一轮 `desktop-v1`：Mac 6/7 通过（含 TextEdit），仅一次试跑，不能作为最终成功率或行业排名。release helper 后续 F01 又失败；补充实际执行模式上下文后，F01 定向两次均通过，其中一次经历过期引用拒绝后重新观察恢复，仍需完整重复集。Windows ARM VM 的 x64 Agent 在 `--version` 即出现 `0xC0000005`，单列环境阻断；Windows 真实模型任务验收尚未完成。
- 失败驱动的下一步：UI 优先项完成后，处理本地 Windows VM 后台测试准备时目标仍处于前台的阻断，再补全 Windows 基线；Mac 优先处理窗口身份稳定性、滚动可见性与过期引用恢复。Chromium 后台滚动仍按现有能力边界暂停；`desktop-v1.1` 加严滚动用例，要求滚动发生且目标在点击时完整可见，旧版与新版不能混算。前台状态中断保留失败记录，不自动恢复或切模式。
- 本地 VM 启动修复（2026-10-21 继续）：同版本官方 ARM64 与 x64 baseline Agent 在交互会话均成功输出 `1.17.11`；原安装 x64 构建仍启动失败/超时。已验证两个归档的 GitHub SHA-256，先在独立测试目录使用 ARM64 候选跑真实模型；不替换已安装客户端，不改三个子模块 pin。基准新增模型/窗口启动前的 Agent 预检、PE 架构及退出原因记录；ARM64 候选已完成 F01 真实模型任务（51.7 秒、7 次工具调用、业务 oracle 通过）；其余 6 项被后台准备检查阻断，不能算双平台全套通过。
- Windows VM 前台阻断修复（2026-10-22）：6/7 任务 `backgroundTargetInForeground` 的根因是锚窗 `Form.Activate()` 被 Windows 拒绝（后台进程无抢前台权限），且旧锚窗 8 tick 后无条件写 ready、从不校验。已改为 `AttachThreadInput` 挂前台线程后 `SetForegroundWindow`，并用 `GetForegroundWindow()` 连续 2 tick 校验持有才写 ready；10 秒拿不到则写 failed，运行器显式报 `backgroundAnchorUnavailable`（`scripts/computer-use/bench/real-host.mjs`）。脚本测试 11 项通过；Mac 在跑进程不受影响（runtime 启动时构建）。待 Mac 7×5 完成后重建 runtime.cjs 并在 VM 实测。
- 后续验收顺序不变：先稳定这 7 项并补足每项 5 次，再扩充 50+20 任务及留出集，随后做真实业务软件/物理输入与窗口生命周期矩阵、双平台签名安装包、8 小时稳定性，最后优化 token 和耗时。本轮未提交、推送或发布。
