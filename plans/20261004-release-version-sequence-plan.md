# 发布版本序列修正

- 依据：用户要求合并 Windows 登录/安装修复，并使用正常 `X.Y.Z` 版本，beta、stable 交替且不重复。
- 范围：只合入 `codex/windows-login-persistence` 的剩余安装器修复；修正现有 release 入口的版本预检与发布文档。不合入未经提测的需求，不移动历史 tag，不发版。
- 默认沿用当前 `3.0.x`：已发布 stable `3.0.7`，下一版 beta `3.0.8`，之后 stable 使用新版本 `3.0.9`。版本线切换不由本轮自动执行。

## 实施

1. 检查并合入安装器 `ClearErrors` 修复，保留并行工作区与子模块改动。
2. 新 tag 在远端两通道中检查数字版本唯一；同一 `X.Y` 版本线递增且通道交替。使用实际上一版通道，不硬编码单双号。
3. 同 tag、同 SHA 可续跑构建/签名；同步不得降低 S3 或 OSS 当前通道版本。不同 SHA 禁止改 tag。历史重复版本只允许已有 tag 续跑。
4. 新 tag 创建前再次核对远端，避免预检后已有版本变化。
5. 修正旧文档中同号转正和删除 tag 重打的说明。

## 验证

- 发布入口回归：跨通道同号、同通道连续发布、版本回退、数字排序、annotated tag、正常交替、历史 tag 续跑及预检后远端变化；独立复核发现旧版续跑会降级更新指针，追加失败回归后修复。
- 运行现有打包配置与脚本质量门；本轮不宣称已重新通过 Windows NSIS/正式安装包验收。
- 提交仅包含本轮文件，不提交前端被并行任务更新的 gitlink，也不清理基座 overlay。
