# Linux DEB 连续升级修复

## 复现和范围

统信 UOS 20 ARM64 从 Beta.8 自动重启到 Beta.10 后，下一次安装 Beta.15 时 `pkexec` 报 `pkexec must be setuid root`。从桌面重新打开 Beta.10 后，同一个安装包可以授权并升级，Beta.15 自动重启的进程再次出现 `NoNewPrivs: 1`。

在同一台设备上用 Electron 43.8.12 的独立进程验证，`app.relaunch()` 会使 `NoNewPrivs` 从 `0` 变为 `1`，使用普通用户进程等待旧实例退出后再启动可保留 `0 → 0`。操作系统预设 `1` 时仍保留 `1 → 1`。 [Electron 上游问题 #55528](https://github.com/electron/electron/issues/55528)

本次覆盖 Linux DEB 客户端内升级，系统权限和安装授权继续由 polkit 管理。

## 实现

- 非 root 安装前从 `/proc/self/status` 检查 `NoNewPrivs`。为 `1` 时保留下载包，提示用户完全退出并从桌面重新打开。状态不可读取时沿用系统授权。root 仍直接执行安装脚本。
- DEB 安装成功后，复用 Electron 内置 Node 以当前用户启动独立重启进程。重启进程等待旧 PID 退出后才打开已安装的新版本，保留启动参数和桌面会话环境。等待超时或启动失败写入更新日志。
- 重启进程启动失败时保留正在运行的客户端及服务，提示更新已安装，需要从桌面重新打开。旧实例阻止再次调用安装器。

## 验收

- 定向测试覆盖授权预检、root 直装、安装和重启的顺序、重复安装防护、旧进程退出前后的启动行为。
- 用本次实现跑过两次连续的隔离重启。UOS ARM64 使用 Electron 43.8.12，Ubuntu x64 使用 Node 22。普通进程均为 `0 → 0 → 0`，受限进程均为 `1 → 1 → 1`。
- 在 UOS ARM64 和 Ubuntu DEB 用包含修复的客户端连续安装两个递增版本，中途不手动重开。核对两次系统授权、自动重启、新进程 `NoNewPrivs` 及服务恢复。已发布的旧版仍按其自身的重启逻辑运行，验证应从桌面启动的修复版开始。
