# 本机文件路线兼容与设置开关

状态：实施中。依据本次用户要求，在现有能力契约和特性配置上补兼容与设置入口，不增加接口版本，不改已发布 Beta.4。

## 行为

- direct 模式允许 PC Web 先升级；浏览器、无本机桥、v1 只读桥、缺少完整 v2 文件能力时，保持原文件服务路线，读写行为一致。
- 新客户端具备完整 v2 能力并命中当前电脑/会话后，文件操作走本机；已确认本机的权限失败、上下文失效和迟到保存不转为旧路线重试。
- 客户端「设置 → 系统」增加本机文件访问开关，复用 `features.local-files.enabled`。缺省开启，保留已保存的 false，独立于 `step1_config` 和页面本地化模式。
- 设置保存后重启客户端生效，界面明确提示。关闭后重启不注册特性，PC Web 自动沿用原路线。读取/保存失败必须可见，不显示虚假保存成功。
- 用户确认本轮只优化文件操作体验，以 Codex 的清晰状态和紧凑操作为参考：修正自动保存回执，按文件合并编辑并串行提交；展示当前文件的未保存/保存中/已保存/失败状态，支持 Cmd+S（Mac）/Ctrl+S（Windows、Linux）与失败重试；系统打开/定位按钮有等待反馈并防重复投递。

## 改动范围

- 前端 `features/client-shell/localFileService.ts` 的能力准入与服务层兼容回归；基于当前 `feat-2026.9.30`，保留其他页面更新。
- 客户端 SettingsPage、共享本机文件配置常量、设置类型校验和四种客户端语言；不在通用设置存储中混入文件 I/O。
- 复用特性注册的默认/显式开启/显式关闭语义；无需新增动态特性生命周期或写桥契约。
- 文件面板及 Chat 共用带真实 Promise 回执的按文件保存器；切换会话/关闭时取消尚未投递的保存，已有请求的迟到结果不能覆盖新来源状态。不调整整体客户端布局。
- 用户补充的 Computer Use 弹窗遮挡：删除主进程在等待目标窗口时自动打开操作中心的行为；运行状态与历史继续记录，仅用户点击操作入口时打开。关闭详情不停止任务。

## 验证

1. 先复现旧桥/缺失写方法的读写兼容缺口，再修正能力选择；保留本机错误不回退、跨会话/电脑及迟到写入保护。
2. 测试配置缺省开启、保存 false 后回读、保存失败不落 UI 状态、旧值 false 不被升级重置。
3. 运行前端文件/宿主桥分域、架构检查及相应类型域；客户端设置与文件/桥/特性注册测试、host-bridge/overlay/pin 检查。
4. 改动如需提交前端新 pin，先推前端分支，再固定客户端 pin；此轮不启动新的独立验证包或创建新发布 tag。

## 回退

新客户端通过开关关闭并重启，回到原文件服务路线；旧客户端无需升级即可继续原路线。本机路线一旦选定，其在途操作保持原有失效/取消语义。
