# DSH 原生插件工作台实施计划

## 目标

以 DSH Host/Client 插件生态承载 Nuwax 页面和本地生成组件。ACP 管理 Agent 执行，配置与 MCP 调用同一组工作台能力。首批贯通文件、终端和用户/Agent 共用浏览器。

## 基线与版本

- 基线为扩展集成分支 f70c784c，实施分支为 codex/dsh-dynamic-workbench。
- DSH 0.2.1-rc.5，better-sidebar 0.28.2，沿用现有账号隔离和宿主授权。
- 工作台使用独立 Profile，启动与 DS-Bot 模型授权解耦。
- 页面与 Agent 的会话身份由主进程验证。文件服务未就绪时报告实际失败，支持重试。

## 阶段

1. V0 完成真实插件加载、工作台入口、会话映射和浏览器/MCP 兼容原型。
2. V1 将文件、终端、浏览器作为 DSH 原生插件接入现有会话。
3. V2 提供组件发现、布局、配置、锁定、撤销和恢复能力。
4. V3 提供本地插件生成、构建、预览、版本激活与保存。
5. V4 建立故障清单、候选修复、场景验证与回退闭环。
6. V5 按依赖拆分首批业务页面，处理个人修改与产品升级兼容。

## 验收

- 原包安装/加载/禁用/恢复，覆盖实际 Client 挂载。
- 真实 DSH 会话与业务会话绑定，切换、并发、失效和重启可恢复。
- ACP Agent 经授权 MCP 操作界面，返回实际结果。
- 浏览器使用同一页面实例，支持人工接管并撤销自动化连接。
- 文件首次不可用和首次解析失败均可重试恢复。
- 布局并发修改检测、模块加载失败与最近有效版本恢复。
- 源码定向测试、真实 Electron 测试分别记录证据，安装包验收单独执行。

## 实施进度

- 已核对集成基线，原有 DSH 定向测试 19 项通过。
- V0 已打通独立 Profile、原生插件管理器、DSH Agent/Session 生命周期和 ACP 会话专属 MCP。
- V1 首批文件预览、原生终端、共享浏览器已接入独立工作台窗口。
- V2 已提供组件发现、布局版本检查、用户布局锁、显隐、分栏、浮动、尺寸及原生撤销/重做。布局适配绑定 DSH 0.2.1-rc.5。
- 真实 Electron 已覆盖 better-sidebar 0.28.2 的安装、Client 挂载、禁用和恢复，文件内容、终端执行、浏览器接管、会话隔离及布局保护。
- 商业回归 3,832 项通过、1 项跳过，DSH 定向测试 23 项通过，前端定向测试 65 项通过，主进程类型检查和构建通过。
- V3–V5 继续按后续批次交付，本批 PR 面向 alpha/v3.1.0，真实安装包与其他平台验收另行安排。

## 云端续做交接

用户已授权把剩余开发移到云端；云环境无法运行项目或 Electron 时，可先编写代码，暂不执行逻辑验证。新增行为必须标注为未验证，不复用上述历史结果作为新代码通过的证据。产品运行时的插件激活、隔离和修复验证门禁仍须实现。

当前起点为客户端 PR [#95](https://github.com/nuwax-ai/nuwax-client/pull/95) 与前端 PR [#240](https://github.com/nuwax-ai/nuwax/pull/240)，均使用 `codex/dsh-dynamic-workbench` 分支。继续前核对实时状态，保留他人改动。后续代码分批提交到最新 alpha 分支，不自动合并、发布或更新产物仓 pin。

按以下顺序完成可用代码批次：

1. 补齐 V1/V2 的生命周期和失败恢复。覆盖文件服务首次不可用、首次工作区解析失败后的主动重试；错误保持本机来源，不回退到云文件。会话切换、账号失效和插件卸载应释放调用授权与资源。
2. 完善组件配置、布局保存恢复和真实挂载结果。当前独立工作台只覆盖右侧、分栏及浮动；全客户端左侧文件、右侧浏览器、底部终端的布局仍需实现。配置、用户操作和 MCP 共用状态入口，保留版本冲突、用户锁、撤销及浏览器实例。
3. V3 先交付可使用的完整流程。源码写入当前产品本地数据目录，经构建检查、隔离预览、指定版本激活和挂载后，可保存到会话、工作区或个人范围。沿用 DSH 原生插件生命周期，包含可调用入口和 MCP。明确受限 UI 与受信 Node 服务的能力边界，保留最近有效版本和失败回退。
4. V4 实现故障清单及候选修复。关联版本、会话和复现证据，区分疑似、已复现、修复中、待验证及已验证；支持用户选择自动或手动处理。候选修复经过运行时检查后激活，失败回退，记录尝试次数和模型费用。云端未执行检查的修复保持待验证。
5. V5 选择依赖可控的真实业务面板，拆分界面、功能服务及 DSH 插件适配，逐批迁移并处理状态保存和升级兼容。终端维持当前生命周期，持久化和多终端继续另行安排。

云端接续只修改 Nuwax 客户端及所需的 nuwax 前端源码，不修改借用环境中的其他项目或 agent-platform。前端变更须先推送对应提交，再更新客户端源码 pin 与宿主桥快照。

## Alpha 后续批次：布局方案与操作反馈

- 从最新 `alpha/v3.1.0` 开发，PR 只面向 Alpha，暂不进入 Beta。
- 补齐 V2 的会话布局方案：用户与 MCP 共用保存、读取、应用和删除入口；按账号窗口分区及会话隔离，跨工作台重启保留。
- 保存面板种类、导航参数、分栏、浮动位置和尺寸；应用时使用原生操作恢复，复用仍存在的面板及浏览器实例，重新打开已关闭面板。额外打开的面板不自动关闭。
- 布局应用继续检查当前布局版本与用户锁，方案写入使用独立修订号；恢复前验证全部面板依赖和数据，遇到缺失插件或损坏存储返回实际错误。
- 原生布局操作补齐必填参数、会话内资源身份和执行结果校验，拒绝把无效操作报告为成功。
- 本批做定向源码与真实 Electron 验证；V3–V5 接续此前清单，不将本批描述为完整动态插件或自动修复交付。

本批已实现命名方案和用户锁的主进程持久化、修订号并发检查、原生面板恢复、分栏比例调整、公开插件配置 MCP，以及无效布局操作的实际反馈。持久化不依赖临时 HTTP 端口。恢复失败时只撤销本次尝试产生的历史操作，额外面板保留；合并停靠栏会导致同类页面去重时拒绝该恢复。

当前定向验证：DSH 33 项、MCP 6 项、资源脚本 7 项通过，主进程类型检查和分层检查通过。真实 macOS arm64 Electron 已验证命名方案、关闭面板重开、两栏比例、浏览器实例保留、会话隔离、重启方案及用户锁恢复。安装包和其他平台仍待验收。本轮 better-sidebar 在线安装复验两次超时，尚未完成当前批次的该项兼容验收，不将既有批次的兼容结果追认为当前结果。
