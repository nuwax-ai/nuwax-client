# 意图：统一宿主能力探测与截图录屏复制

- 日期：2026-10-14
- 状态：已接受；依据用户要求实施 canUse、交接文档、复制按钮和控制条阴影调整，及对截图复制图片、MP4/GIF 复制文件的明确确认。

## 问题

业务页在普通浏览器、旧客户端或不受信页面里运行时，不能靠一个同名方法存在就判断客户端能力可用。IM 需要可直接交接的能力说明、原会话附件回填方法与实际接线位置。截图录屏预览仅支持保存，缺少复制；录制控制条下方出现多余的系统阴影。

## 预期结果

- 页面通过统一 canUse 查询公开能力；普通浏览器、未知能力、非当前受信业务文档和关闭的特性得到 false。
- IM 团队获得能力清单、API 和可直接交给 Agent 的接入文档，截图/录屏完成后回填发起会话的待发送附件，复用原发送链。
- 截图可复制为图片；MP4/GIF 可复制为原始文件，关闭预览后仍可粘贴，GIF 保留动画。
- 录制控制条的系统窗口阴影关闭。

## 受影响的能力面

公共桥契约、preload 能力查询、主进程信任门禁、采集结果复制、三端剪贴板适配、宿主预览 UI、语言资源与 IM 交接文档。

## 约束

- 保留独立 IM 项目边界，不增加 IM 后端或消息协议，不改业务登录注册链。
- 查询是环境/能力探测，不代表权限已经授予或本次操作必然成功，不触发采集、保存或授权弹窗。
- 协议增量兼容旧宿主；业务页仅接触不透明句柄，不获取原始文件路径。
- Clipboard 文件导出是用户主动操作；关闭预览释放结果原件，已复制的独立副本保留在受控缓存中。
- 平台实现放在平台适配模块；PNG/JPEG 复制图片，MP4/GIF/WebM 复制文件；不把视频/GIF转换为静态图片。
- 保留已有工作区的子模块改动，在独立 worktree 实施；本轮不自动发布新 beta。

## 已确认与验收边界

- 用户已确认：截图与录屏都支持复制，包含 MP4 与 GIF。
- IM 当前本地基线 518be4d 已有 pendingByConvRef；addPending 仍只面向当前会话，需 IM 团队接入按目标草稿追加。
- 文件粘贴依赖目标应用支持原生文件剪贴板；客户端能力与 IM 真实收发分别验证。
