# Windows 安装与升级的跨版本加固

## 结论与边界

用户报告 Windows 11 22631 / 26200 安装未完成即退出，无法取得原包或机器验证。当前无相应 build 黑名单；不能据此认定为 Windows 版本缺陷。应按能力、权限与失败阶段处理，不按营销版本猜测。

源码风险：

- NSIS 安装、覆盖与自动升级依赖 Windows PowerShell/.NET、动态 C# 编译及临时目录。磁盘检查虽在旧文件保全前，但应用内升级已先清理服务并退出。
- electron-updater 6.8.3 的 NsisUpdater.doInstall 返回的是启动尝试，BaseUpdater 随即退出应用，不等待安装器完成。现有 try/catch 不能证明安装成功。
- 一键升级仍允许 SDK 的退出时静默安装，可能绕过主进程安装前检查。
- builder 25.1.8 的模板只排除 Vista 及以下，却允许 Electron 40 已不支持的 Windows 7/8/8.1；补 Windows 10 下限和显式 SupportedOS manifest，避免现代系统被旧版本 API 误判。
- 已有恢复错误日志，但缺少从初始化开始的统一阶段记录；插件原生崩溃不能由 PowerShell catch 捕获。

现有保护：原生 System::Store 已规避；ZIP 直解压、空间预检、原路径/账户/范围核验、事务恢复和未知文件保全已存在。本工作不删减这些边界，不改已发布版本。

## 实施

1. 共用签名可覆盖的 `installer-runtime.ps1`：探测 PowerShell 5.1、当前临时目录读写和安装需要的 Add-Type/PInvoke 能力。只创建并清理自己的临时探针，不动安装登记或用户文件。受信脚本在策略下的实际能力决定结果，不擅自更改执行策略或关闭安全软件。
2. Windows 资源打包同一脚本，主进程用系统 PowerShell（优先与 NSIS 一致的 x86 宿主）、固定参数、无 shell、有超时执行。成功标记与进程退出码共同确认；失败发生在 markQuitting/服务清理之前。
3. Windows 一键升级禁用 SDK 的退出自动安装旁路；环境失败保留下载包和错误状态，可重试。普通分步更新的退出安装策略不在本次改动范围。
4. 安装器在旧文件操作前探测环境；从 preInit 的首个插件调用之前记录阶段、系统 build、安装范围和退出码。记录完成/失败/界面退出，不把启动安装器等同于安装成功。

## 追加：安装结果回执与启动恢复（用户授权实施）

- Windows 显式升级由签名覆盖的独立 PowerShell 监控脚本接管安装启动，SDK 继续负责下载、完整性与发布者校验；不使用 SDK 私有字段。监控脚本先就绪，客户端完成清理并写提交标记后退出，监控器等待原客户端结束再启动安装包。
- 每次使用 UUID，在当前产品数据目录 `updates/<安装路径摘要>/<id>/` 原子保存任务、状态和确认记录，多个安装副本分别索引。任务记录目标版本、原路径、下载包 SHA512、监控脚本 SHA256；脚本读取的任务摘要由进程参数锚定，安装前锁定并复核下载字节，拒绝换包。监控器始终以发起用户权限写回执，即使安装器跨 UAC 提权；不让提权进程按外部路径写文件。
- 退出码非零记录失败；退出码零只表示安装器退出。下次启动的实际版本与原安装路径都符合目标，才确认成功。缺失、损坏、中断、版本不符和未确认的回执保留，并给恢复提示。另一副本不消费本副本的回执。一次提示可稍后处理，诊断证据继续保存。
- 安装器接收 UUID 仅用于日志关联，不基于该参数授权任何路径或清理。历史安装器忽略未知参数也可使用监控器，通过退出码和后续版本核对判断结果。
- 非零退出或成功退出后迟迟未确认，监控器给出可见提示；若监控器自身被系统终止，持久任务仍供下次启动检测。不自动运行回执里的任意程序，不自动删除数据、不自动放宽恢复核验。
- 与 PR #128 的结合：新增 `.ps1` 必须在原应用载荷中，沿用内层扫描、CI 来源摘要、签名后卸载摘要和最终重新解包验签；本地复制监控脚本保持完整签名字节。该聊天当前正在用固定的旧 3.1.3 载荷验签，不能把其结果当作本次新增脚本的实包验收。
- 同版本补签包重装不能单凭版本号确认。新安装器在保全恢复与快捷方式处理完成后，按事务 ID 将完成标记写入原用户 HKCU 的固定产品键；UAC 内层使用现有 AsUser 回调。监控器读取该标记进入回执；同版本升级只有标记、退出码、版本及路径同时符合才确认。历史安装器没有标记时保守提示未确认。
- 固定 SDK 的 UAC 插件会将内层退出码设置到外层 NSIS error level（源码 `templates/nsis/include/UAC.nsh`）；仍保留运行版本/原路径确认以防退出码零代表取消。跨账户交互 UAC 尚未实包验收。

## Beta.4 发布前质量自查

- 内聚：任务、回执和启动核验集中在 `src/main/services/windowsUpdateSession.ts`；安装器执行与父进程等待集中在 `build/installer-monitor.ps1`；`autoUpdater.ts` 只编排预检、提交与恢复提示。回执不授权执行历史路径或删除用户数据。
- 分层：SDK 保留下载与发布者校验，Windows 监控属于主进程服务与安装层；renderer 不读写事务文件。原用户回执与 UAC 提权安装分开，完成标记沿用既有 AsUser 回调，未知旧安装仍由现有恢复契约核验。
- 可维护：schema、目标版本、安装路径、文件摘要和成功标记均有运行校验与回归覆盖；记录大小及等待上限使用具名常量，活动任务检查不依赖错误文案。NSIS 清单最终化与物理 NSIS 任务副本绑定，失败即停止打包。
- 结论：三问通过；复用同批源码的定向与 Windows 原生夹具结果，发布集成继续由 PR/tag 的完整 CI 门禁执行。此自查不替代 PR 评审，不进行 writer 自批。
