## 架构前提

- **Nuwax Computer Use**：独立运行程序，内含我们从源码构建的 cua-driver（mac `Nuwax Computer Use.app`，标识 `com.nuwax-ai.nuwax-computer-use`），随 Nuwax 客户端安装、由客户端拉起，持有辅助功能和屏幕录制授权。桌面类工具和浏览器类工具（`browser_*`，通过浏览器调试协议后台操作网页）都由它执行。
- **主进程网关**：鉴权、会话控制权、白名单、预算、暂停和停止（`overlay/.../cua/mcpGateway.ts`、`taskController.ts`、`windowScope.ts`）。本期改动集中在这一层，不改 Nuwax Computer Use 程序本身。
- **Agent 引擎**：只能通过网关调用工具。

## 问题

主进程网关的设计偏向"防出事"，没有把"任务能完成"当目标，导致任务频繁中断，网页任务受影响最大：

1. **报错就停机。** 任何一次工具报错（比如找不到元素）都会暂停任务，并关停 Nuwax Computer Use 守护进程，必须由用户点恢复（`taskController.ts:109`、`mcpGateway.ts:179`、`computerUse.ts:1032`）。可是元素找不到、引用过期这类错误，Agent 重新观察一下就能自己恢复；网页一跳转，旧的元素引用就会全部失效。
2. **重复判定太粗，而且不可恢复。** 同一工具、同样参数连续超过 3 次就判定为"重复动作"，且不允许恢复（`taskController.ts:83`、`:133`）。连续滚动、用方向键选择这类正常操作会直接终止任务。
3. **浏览器和桌面共用一把全局锁。** 整台桌面只允许一个使用者；浏览器类工具在后台执行、不占用鼠标，也会被"桌面忙"拒绝（`taskController.ts:65`）。
4. **"先观察再动作"不区分目标。** 观察了 A 窗口，就能操作 B 窗口（`taskController.ts:78`）。安全上的保证比看起来弱；同时每个动作后都强制重新观察，让表单这类连续操作的步数翻倍。
5. **限定窗口模式排除了浏览器。** 用户没法做到"只允许操作这个浏览器窗口"（`windowScope.ts:12`）。
6. **没有工具选用指引。** 大约 50 个原始工具直接交给模型，网页该用浏览器类工具还是像素点击，全靠模型自己判断。
7. **没有任务成功率的度量。** 现有验收覆盖的是安全控制和签名，没有衡量任务是否完成、用了多少步、打断用户几次。

## 预期结果

1. **错误分级。**
   - 可恢复错误（元素不存在、引用过期、页面已跳转）作为结果交还模型，计入预算，不打断任务。
   - 结果不确定（超时、连接中断）时暂停，等待用户处理。
   - 越权或违反安全规则时直接停止。
   - 只有第三类才关停 Nuwax Computer Use 进程。
2. **"无进展"判定。** 同一动作重复执行、且前后观察到的界面没有变化，才判定卡住；触发后允许用户人工恢复一次。正常的连续滚动、按键不受影响。
3. **按资源加锁。** 桌面前台输入（鼠标、键盘、像素点击）全局只允许一个使用者；浏览器类工具按页面加锁，不同会话可以同时操作各自的页面，也不阻塞桌面任务。
4. **观察对应目标。** 写操作的目标（窗口或页面）必须与最近一次观察的目标一致。连续操作同一目标时，不强制每一步都重新观察，但要设上限。
5. **限定窗口模式支持浏览器。** 限定到某个浏览器窗口时，允许对这个窗口对应的页面使用浏览器类工具，其他页面仍然拒绝。
6. **工具选用指引。** 告诉模型：网页内容优先用浏览器类工具；原生应用、跨应用操作，以及浏览器自身的界面（权限弹窗、系统文件选择框）用桌面工具；浏览器类工具走不通时可以改用桌面工具，但改用之前必须重新观察，并确认上一个动作是否已经生效。
7. **基准任务集。** 覆盖网页类和原生应用类任务，记录成功率、步数、人工介入次数和耗时。改造前后各跑一次做对比，作为本期的验收依据。
8. 现有的会话控制权、暂停和停止、撤权、操作记录脱敏、签名包等能力保持不变，相关测试继续通过。

## 功能范围

**本期做**：上面预期结果的 1 到 7 条，以及对应的单元测试、协议测试和基准任务集。

**后续另立**：客户端内置浏览面板（由主进程直接驱动、不需要系统授权）。它涉及面板放在哪里、网站登录态的生命周期、本机和内网地址的访问策略等问题，都与本期无关，届时单独评估。

**明确不做**：

- nuwa-browser 整合
- 修改 Nuwax Computer Use 程序本身（cua-driver 补丁）
- 社区版
- 绕过网站的反自动化机制或验证码

## 状态

- 任务阶段沿用现有的运行、暂停、停止、失败、完成。
- 暂停原因细分为：用户暂停、结果不确定、无进展、预算耗尽、越权。其中"无进展"允许人工恢复一次；"预算耗尽"维持现有规则，不允许恢复。
- 锁的归属记录到具体资源（桌面，或某个页面），不再只有一个全局归属者。

## 异常场景

| 场景 | 预期处理 |
|---|---|
| 页面跳转后元素引用失效 | 作为可恢复错误交还模型，提示重新读取页面 |
| 浏览器类工具因调试端点未就绪而被拒 | 作为可恢复错误交还模型，并提示准备步骤 |
| 工具超时 | 结果不确定：暂停，不自动重试 |
| 两个会话争用同一个页面 | 后来者被拒绝，并给出明确原因；不影响先到者 |
| 一个会话在操作桌面，另一个会话要操作网页 | 网页操作照常进行（前提是没有动用桌面输入） |
| 限定窗口模式下调用其他页面或像素输入 | 越权：拒绝并停止 |
| 用户在任务进行中暂停、停止、登出 | 沿用现有撤权逻辑，不能退化 |

## 约束

- 只改商业 overlay，不改社区基座；提交前跑 `npm run check:pin`。
- 不改 Nuwax Computer Use 程序本身，只改主进程网关和给模型的说明。浏览器类工具的实际行为，以我们打包的 cua-driver 0.28.2 为准；目前看到的工具说明来自本机官方 0.21 版，要用我们自己的 Nuwax Computer Use 实测确认。
- 保留一次性授权方式和会话凭据机制。
- 质量门：商业 `npm run test:commercial`；社区 `npm run base:test`（在隔离副本里跑）；真机和安装包验收单列，不能用模拟测试代替。

## 开放问题

已按默认值处理（详见规格，负责人可随时推翻）：

1. **浏览器类工具用哪个浏览器** → 整个桌面模式下只允许另开隔离浏览器；接管用户自己的浏览器只能在限定窗口模式下、对用户选中的那个窗口进行（规格 R4）。
2. **基准任务集** → 规格给出初版 7 个任务；本期不设硬性及格线，以改造前后对比为验收依据。
3. **"无进展"后的恢复** → 不限次数，每次由用户决定。
