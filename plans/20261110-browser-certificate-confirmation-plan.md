# 浏览窗口证书风险确认

## 目标与边界

IM 等入口打开 HTTPS 外链时，遇到自签、过期、地址不匹配等证书错误，由客户端原生确认框说明站点、原因与信息泄露风险，默认取消；用户主动选择继续后加载原请求。

- 仅浏览功能拥有的远端 WebContents 处理证书事件；主窗口和其他服务保持原有校验。
- 原生 Chromium 将证书例外缓存到 session，按主机和证书复用。本次运行期间，同一共享浏览会话的其他窗口也会生效；确认文案明确说明，其他主机和不同证书仍需确认，重启后失效。不承诺关窗或退出登录会清掉 Chromium 内部缓存。
- 未授权的子资源不弹出无关站点确认框，也不自动放行。取消、关闭、停止、导航变化与对话框异常均拒绝尚待确认的请求；迟到确认无效。
- 使用原生按钮处理选择，不增加网页 bridge 或全局证书忽略开关；本次不改变 HTTP 明文和其他 URL 访问策略。

## 实施与验证

1. 浏览窗口挂载独立证书确认模块，同步四种现有语言和 key 注册。
2. 单测覆盖默认拒绝、显式允许、并发确认及尚待确认请求的生命周期撤销。
3. 使用隔离数据目录和本机自签 HTTPS fixture 验证真实 Electron 证书事件、确认后加载、共享会话复用、其他主机/证书/session 隔离及重启失效；不替用户放行实际站点的安全警告。
4. 运行浏览功能、语言一致性与主进程类型检查；安装包另行验收。

## 真实灰屏回归

安装包接受证书后，主文档与灰底已显示，宝塔登录表单仍隐藏。加入与客户端一致的响应头处理、入口 HttpOnly Cookie、带凭据的模块脚本与导入依赖后，真实 Electron 复现了子资源的二次证书事件；原实现拒绝该事件，脚本没有运行。按已告知的 session/主机/证书范围记录用户确认，同源后续资源复用完全相同的证书与错误类型，跨会话、其他主机、证书或错误变化仍须独立处理。新用例断言脚本最终显示登录区域，并覆盖进程重启后的失效。
