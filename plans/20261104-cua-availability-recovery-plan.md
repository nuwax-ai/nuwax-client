# 实施计划：CUA 配置热生效与故障自愈

- 日期：2026-11-04
- 状态：源码实施完成；安装包与真实业务验收由用户执行。
- 用户目标：保留 Nuwax Computer Use 的可用性；用户动态修改配置后在原聊天中热生效；底层进程或连接短暂故障可自行恢复。
- 范围：nuwax-client 商业壳的 Computer Use、MCP 网关与会话参与者；不涉及 agent-platform。
- 交付方式：一份计划记录实现与证据；按用户后续要求，代理负责代码，验证由用户执行。不触发打包、部署或真机重启。

## 证据与当前缺口

现场证据保存在仓外；原始业务日志与账号信息不随 PR 上传。

win-dbg 的 3.1.1 在 20:31:25 停止 CUA daemon，20:31:28 重新启动并注册 MCP；原 ACP 会话随后连续返回 Transport closed。稍后 metadata 探活与端点身份校验通过，驱动版本为 0.38.0。现有日志不能确定此次停启由哪个设置或控制动作触发，也尚未验证新会话能否恢复。

当前检出源码提供了相符的故障路径，但尚未核对安装包内每一处实现：
- mcpGateway.ts 的 attachDriver 在子进程 error/exit 时关闭整个 Agent 连接；stdio relay 随 socket close 退出。
- computerUse.ts 的 suspendCuaRuntimeResources 关闭网关、移除 MCP 条目并停止 daemon；recoverCua、setCuaScope、setMultiwindowEnabled 共用该清理路径。
- 已有 pauseTransports / resumeTransports 能保留 Agent 连接并重新 initialize 底层进程，应扩展复用，避免再做一套独立恢复系统。
- 健康监控每 30 秒调用 getCuaStatus；状态读取可能触发破坏性清理，清理后监控停止，没有持续自愈。
- 授权模式、黑名单已有调用时读取，但设置与在途动作之间缺少统一版本屏障；光标 setter 只保存偏好，活跃连接的 cursorArmed 不会据此即时更新。
- VLM 配置当前由 vlmDiagnostics.ts 用于诊断测试，不能把修改该配置描述为现有执行模型已经完成热切换。

## 目标与不变量

1. 已有聊天无需重开即可使用最新配置；关闭再开启、切模式或底层恢复，不让原会话永久失去 cua 工具。
2. Electron 主进程存活期间，MCP 前端入口稳定；原生 daemon、MCP 子进程与策略可在其后受控替换。
3. 服务可用状态与任务控制状态分开。服务恢复不能把用户暂停、接管、停止或已撤权的任务变回运行态。
4. 不自动重放点击、输入、导航、启动应用等可能产生副作用的请求；未知结果必须保留为未知。
5. 恢复后重新校验身份、当前策略、会话授权和实际目标，废弃旧 snapshot、element token、browser ref 与一次性批准。
6. 每个调用最终只回应一次，旧进程的迟到响应不能计为成功；跨会话、跨登录代次与开发/正式实例保持隔离。
7. 全局退出、注销、换域与关闭功能立即撤销执行权。自愈仅在当前登录有效、用户仍启用功能且策略有效时运行。
8. 主进程退出或系统无法提供交互桌面不属于透明续跑范围；下次启动可恢复服务与偏好，旧动作和旧授权不自动恢复。

## 配置热生效规则

热生效以“保留聊天和 MCP 前端，运行时应用新配置”为准。原生协议不支持原地修改的配置，执行有界 drain 后重建底层服务。

| 配置 | 生效规则 | 对当前任务的影响 |
|---|---|---|
| 模拟光标、预览显示偏好 | 保存后向活跃连接更新，后续新连接也读取最新值 | 保留任务与窗口绑定 |
| 授权模式 | 下一次派发使用最新策略；切到 ask 清除未消费批准，并处理尚未派发的写动作 | 需要确认的动作进入现有确认流程 |
| 黑名单 | 新增限制立即屏蔽派发并撤销命中目标的原生租约，等待 drain；移除限制后重新观察与校验 | 仅影响命中任务；解除黑名单不自动恢复已暂停任务 |
| 目标窗口、窗口/桌面范围、单/多窗口模式 | 暂停受影响任务、撤销旧租约、清空旧观察/批准，应用策略并受控切换 driver；保留聊天连接 | 旧任务不能自动跨目标迁移；新目标由用户选择并重新绑定，扩大权限沿用现有确认 |
| 前台/后台执行模式 | 沿用目标级暂停与 drain，确认授权后应用 | 前台权限不自动提升；受影响任务重新观察后按现有继续流程恢复 |
| 功能关闭 | 立即拒绝新动作并撤销原生执行权，停止助手；稳定 MCP 前端返回 disabled | 不自动恢复原任务；关闭不生成重启重试 |
| 功能重新开启 | 已有登录与系统权限允许时启动最新配置的助手；原聊天入口重新可用 | 旧暂停/停止状态保留；新的合法调用可以建立新任务 |
| VLM 诊断配置 | 下一次诊断采用新配置；端点变更继续清除旧密钥，禁止旧密钥发往新端点 | 不重启原生助手，不宣称改变执行引擎模型 |
| 系统辅助功能/录屏权限 | 只读探测实际授权；丢失后立即停止受影响执行 | 显示等待用户授权；自愈不自动操作系统授权界面 |

“立即”指宿主接受修改后不再放行旧策略的新动作；已经进入 OS 的动作只能撤销后等待 drain，界面必须显示尚未完成的交接，不承诺撤回已发生的输入。

## 统一配置协调

在 Computer Use 主进程特性内维护一个协调入口，复用现有 preferences 与生命周期串行队列：
- 配置提交统一做字段校验与来源校验，不允许不同 setter 各自停止/重启服务。
- 区分 desiredConfigRevision 与 appliedConfigRevision；现有 runtime.revision 继续用于界面状态排序，不能混为一谈。
- 配置成功持久化只代表“已保存”；通过运行时策略/能力确认后才显示“已生效”。失败显示失败原因和受限状态。
- 对限制收紧先阻断派发并作废相关租约；持久化失败也不能宣称生效或继续以更宽权限执行。
- 快速连续修改合并为最新目标配置。每个已接受的限制收紧立即执行；旧恢复作业不能重新发布旧策略或覆盖后来的关闭操作。
- reconcile 依据当前实际状态计算最小动作；同值重复提交幂等，健康且策略匹配时不停止 daemon。
- 配置版本、原生服务 generation、授权撤销代次分开记录。所有异步启动/探测/响应回写前比较当前版本与授权代次。
- 若用户在恢复中关闭功能、注销、换域或急停，取消旧恢复作业，迟到成功不得重新启用服务。
- 改配置不会刷新业务任务预算、清除失败证据或抹除历史。recoverCua 不再依靠 clearHistory 表示恢复成功。

## 稳定 MCP 前端与恢复层次

### Agent 到宿主

- 主进程维护稳定的 CUA MCP 协议前端，生命周期与登录宿主一致；将“入口存在”与“允许执行”分开。
- 在新建/加载的已登录宿主会话中提供固定 cua 入口，即便功能暂时关闭，也不启动原生助手或授予动作权限。关闭时工具调用返回明确 disabled。
- 宿主前端可处理 initialize、ping、受审核工具目录及 disabled/recovering 状态，不要求每次握手都先启动原生进程。
- 工具目录使用与随包 helper 协议版本匹配的审核集合。不能依赖模型重新 tools/list 才落实权限变化；每次派发均以当前策略重新校验。
- 复用 cuaSessionNotice 的版本提示，在下一安全模型交互及工具返回中说明配置变化、恢复和重新观察要求，提示本身不构成授权。
- 已创建但没有 cua 条目的旧会话需验证 ACP 适配器热更新能力；无该能力时，在当前轮安全结束后重新 attach/load 原会话并刷新其 MCP 连接，保留聊天身份与历史，不自动重发整个 prompt。该兼容路径不作为日常配置应用方式。

### 宿主到原生服务

- 将 pauseTransports / warmDriver / resumeTransports 收敛为统一的连接修复路径，保留 Agent-facing socket 和 MCP 初始化身份。
- 单个 MCP 子进程退出只修复该连接；共享 daemon 故障才进入全局服务恢复。一个 owner 故障不能停止健康的其他任务。
- 临时故障不关闭整个 gateway，也不反复删除/注册 MCP 配置。
- 底层重启后重做 initialize、协议能力协商、端点 proof 和当前策略哈希校验；新连接就绪不等于旧动作成功。
- 物理网关连接意外断开时，relay 保留 stdio 前端，执行有界重连与重新握手；只恢复协议控制消息，不重放 tools/call。重连后重新验证仍有效的 session grant。
- relay 仅负责协议连接，不自行启动 daemon、不修改配置、不绕过主进程授权。主进程协调器是服务启停唯一 owner。
- 每次底层 generation 变化使旧观察和 browser 绑定失效。原浏览器仍存在时按可信原生身份重新验证绑定；原目标已关闭则返回 targetClosed / 需要重新选择，不按标题或 URL 猜测新目标。

## 自愈状态与退避

服务状态单独表示 disabled / starting / ready / reconfiguring / recovering / waitingPermission / degraded；任务继续沿用 running / paused / stopped 等既有状态。

恢复触发：
- 子进程退出、命名管道断开等事件立即触发连接检查。
- 活跃任务建议每 5 秒探测；空闲约 30 秒。仅有 metadata 成功不足以标记会话可用，需覆盖相关 MCP 连接与策略有效性。
- getStatus 只返回状态与探测结果；周期监控和协调器负责修复，设置页面读取不另起破坏性清理。
- 确认实际故障再升级恢复层次；单次暂时延迟不重启整个服务。
- 恢复前先阻断受影响派发、撤销原生租约并确认 drain。若无法确认已停止，保持不可执行并报 helperStillRunning，不启动竞争执行者。

初始参数作为待验证的实现默认值：
- 同一个实例同一时间只允许一个协调作业，单连接修复也须去重。
- 快速恢复按 1 / 2 / 5 秒退避并加抖动，单轮总预算 30 秒；失败后冷却 60 秒并低频只读复测。
- 关闭功能、退出登录、用户急停、权限缺失、签名/端点身份失败、协议不兼容均不做盲目重试。
- 持续故障进入 degraded，展示失败原因；有效配置变更或手动“重试恢复”可重置技术故障预算。
- 目标：恢复中的调用 2 秒内收到明确状态，避免 60/300 秒悬挂；正常单次进程故障争取 15 秒内恢复能力。以上均为验收目标，尚无测量结果。

## 动作结果与并发边界

- 每个请求维护 queued / dispatched / settled 状态及唯一终结门。
- 未派发的旧配置动作取消并返回 configChanged；恢复后的新动作必须重新观察。
- 已派发的写动作发生断连，返回 outcomeUnknown / needsObservation，不自动补点、补输、导航或重发整轮。
- 明确无副作用的只读调用，在当前授权与目标仍有效时可有限重试；需要重新绑定时先返回绑定/观察要求。
- 技术故障发生在无在途写动作且任务仍有执行授权时，可自动恢复连接并重新观察；未知写结果需先核验实际状态。
- userPaused、userTakingControl、userStopped、sessionEnded 等状态不因恢复完成自动解除；恢复服务能力与恢复业务任务分别处理。
- 保留原有 native revoke/drain 约束和预算；旧 generation 响应不能释放新 generation 的租约、命中旧批准或更新新任务状态。

## 实施顺序与验证

1. 先增加可追踪日志与现场回归：记录停启 reason/source、desired/applied revision、generation、脱敏 owner/request、恢复耗时、退出码/信号和阶段结果；stderr 仅保留有界且脱敏的故障摘要，不记录密钥、页面正文、截图或原始工具参数。
2. 修稳定 MCP 前端及单连接恢复，复用既有 warm/pause/resume；覆盖关闭再开启与意外子进程退出后同一会话可用。
3. 统一配置提交与 reconcile，实现配置表中的全部热生效规则；覆盖连续修改、收紧权限、原生策略生效确认和失败状态。
4. 接入单实例自愈、健康分层和退避；移除 getStatus 的破坏性收敛及重复启停路径。
5. 验证原聊天、同一轮安全调用和后续轮次，接入状态展示；只有证据缺口才新增专项测试。
6. 在 win-dbg 安装包中做真实链路复验，随后 macOS 权限/暂停恢复回归；CI 构建使用 GitHub Actions。验证包沿用既有 Beta/Stable 基线，同一问题最多 4 次，遵守仓库发布纪律。

必须证明的场景：
- 原聊天先关闭 CUA 再开启，无需新建聊天即可调用；初始关闭时创建的聊天也能在开启后获得能力。
- 连续修改光标、授权、黑名单、范围和单/多窗口模式，最后配置实际生效；设置操作不留下 Transport closed。
- 杀死本实例 MCP 子进程后原 stdio 连接恢复；杀死本实例 daemon 后各受影响连接恢复，健康任务不被无关连接故障中断。
- 在写动作派发后断开，动作执行次数至多一次；迟到响应与重连均不报告虚假成功。
- 恢复期间关闭功能、注销、换域、暂停、接管或急停，后台恢复不能重新放行动作。
- 并发 owner 隔离；授权代次变更、配置乱序、策略保存失败、身份失败、权限缺失和持续崩溃均可解释且有界。
- browser 引用失效后只允许重新观察/可信绑定，旧 ref、旧一次性批准不能继续使用。
- 重复修改与恢复后无多余 daemon、僵尸 relay、重复监听器、未清定时器或泄漏的 capability 文件。
- 真机使用产品正常聊天 -> ACP -> cua relay -> gateway -> helper 完整链路证明恢复；仅 metadata 或模拟进程通过不算安装包业务验收。

验证以 CUA gateway、computerUse、sessionAuthority、taskRegistry 与 ACP 接缝现有测试为基础，补齐故障与乱序用例；执行相关 TypeScript/边界/桥契约检查。集成发布由 CI 执行完整门禁。安装包验收单列记录，不用源码测试代替。

## 风险与回退

| 风险 | 缓解与回退 |
|---|---|
| 稳定工具目录被误认为授权扩大 | 目录与执行权分开；主进程逐次校验，功能关闭与未登录禁止 native 执行 |
| 热生效期间旧策略仍可派发 | 限制收紧先封锁并撤销，drain 后发布 applied revision；应用失败保持受限 |
| 自愈重复执行或多实例竞争 | 单 owner 协调、请求终结门、generation 屏障、未知动作不重放、确认 drain 后才重建 |
| 恢复无限循环 | 分层故障判断、退避/预算/冷却，安全错误等待人工处理 |
| 模式切换的工具目录/协议变化 | 稳定审核目录与实时校验；随包协议版本验证，必要时仅在安全轮次边界刷新 MCP |
| 单项恢复回归 | 回退对应恢复实现，但保留用户最新持久配置和撤权屏障；先置为明确 degraded，不假装 ready 或启用旧的宽权限配置 |

## 尚需实现验证的事实

- 现场停启的真实触发来源需新增日志后确认，当前不能归因到某个用户配置操作。
- 各 ACP 适配器对既有会话 MCP 刷新的支持、浏览器进程在 daemon 异常后的存活情况，需要专项测试确认。
- 恢复耗时、长期资源占用及 Windows 交互桌面的行为尚未测量；方案不能视为高可用验收结论。


## 2026-11-04 实施记录

已实现：
