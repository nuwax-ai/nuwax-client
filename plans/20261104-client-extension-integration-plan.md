# 客户端扩展整合实施计划

目标已由用户接受，依据 `20261104-client-extension-goals-intent.md` 实施。

## 基线与交付顺序

1. 独立分支 `codex/client-extension-integration` 基于 DSH `cdf82ea4`，整合主题 `56a90d28`。保留两套特性、前端主题源码 pin 和 DSH 资源锁；原工作区及冻结安装包验收不改写。
2. 主题服务增加个人副本、完整候选校验、版本条件、多文件事务及持久历史恢复。MCP 首期修改客户端管理的个人主题，关联外部目录可读并可复制，原目录继续由用户编辑和现有监听器管理。
3. 增加通用壳能力 MCP 特性，默认关闭；主题、壳配置、插件管理分别授权。复用现有本地 MCP 登记，使用每轮授权的私有本机传输；每次调用及变更提交前复核授权，登出/换域同步撤销。
4. DSH 使用原生 MCP Client 接入同一服务；连接随授权动态更新，停止后清理。配置仅携带回环连接或本地 relay 元数据，不暴露平台 Key。
5. 首批壳配置开放浏览器链接打开方式，使用现有配置格式；插件管理适配真实 DSH Plugin Manager，保留其核心包保护和重启语义。能力不可用时返回真实原因。
6. 设置页提供范围开关、状态与主题恢复入口，四种语言同步。主题与 DSH 独立窗口的视觉同步另行适配，不隐式宣称覆盖。

## 行为与失败边界

- 主题 ID、包内相对路径和文件类型走现有完整校验；不暴露任意文件读写。内置主题先复制，批量修改成功才发布完整快照。
- 使用内容版本检测外部文件变化；主题恢复保留有限历史，重启后仍可恢复。磁盘写失败恢复原目录与注册状态。
- 全局开关及领域权限由用户在受信设置页控制；MCP 本身没有扩大权限的工具。未登录不启动本地 MCP 服务。
- 授权关闭、账号变更、特性关闭和退出阻断已有连接与排队修改。失败不能报告成已生效。
- 插件安装及移除受单独授权；安装失败返回原生管理器错误。不宣称进程隔离提供任意代码沙箱。

## 验证与交付

- 复用现有主题/桥/网关/DSH 测试；新增针对事务恢复、冲突、越界、撤权、真实 MCP 发现调用和 DSH 工具桥的必要行为测试。
- 主进程 TypeScript、特性边界与桥契约检查；集成完成执行商业完整门禁。
- 使用真实 DSH 与确定性测试模型完成主题修改、应用、恢复与撤权闭环；源码级验证不等于签名安装包验收。
- DSH 原任务的 macOS arm64 Office 新包复验仍由原任务完成；不因本次集成追加出包，不修改 `agent-platform`。
- 不自动合入发布线；前端 pin 含完整主题分支历史，合入发布线前须独立检查当前发布排除项。
