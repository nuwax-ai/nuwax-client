# 计划：Nuwax 客户端 3.1 Beta

## 目标与决定

- 2026-10-19 用户决定：后续客户端需求放到 3.1；先建开发线，完成需求后再发 beta.1。目标首个版本为 `3.1.0-beta.1`，目前不创建 tag、Draft、安装包发布或更新源指针。
- 开发线：`release/v3.1.x`。起点为 `9b8f06984d4131ca16a94261897242ab2336c32a`，已经包含公开 beta.7、Windows NSIS 卸载名称修复，以及对应验证记录。
- 3.0 stable 的历史归档与 main 同步已交给其他人。本任务停止接管 PR #26 和旧 main 的 overlay 兼容记录，不等待归档完成再开始 3.1。
- 本轮独立工作区：`/Users/apple/.codex/worktrees/client-3-1-beta/nuwax-client`。后续代码从 3.1 线开独立 `codex/*` 分支，经 PR 回流；不混入其他工作区的未提交改动。
- 本文件是 3.1 的持续计划。[10 月需求审计](./20261019-october-client-followup-plan.md)保留为版本切换前的历史事实，不再以其中的 3.0 合并安排驱动本任务。

需求来源：[10 月版本规划](https://agent.nuwax.com/repo/doc/Fy9KinwyNzHU6XsH?hide_menu=true)、[团队问题表](https://agent.nuwax.com/repo/doc/xcCBum7Kqz4TVJYU)、[产品问题表](https://agent.nuwax.com/repo/doc/UikwEDyq6NhUP2JM)，以及用户补充的[前端需求指派清单](</Users/apple/workspace/10月版本规划 · 前端需求指派清单（2026-10-19）.md>)（2026-10-19 快照）。

本轮更新是范围建议，不是完成报告或日期承诺。指派清单属于待团队对齐的规划稿；未勾选不等于当前版本尚未实现，表中模块、负责人及用户猜测也不能直接作为根因。后文的 U-* 标签仅对应该快照，执行时须同时保留原问题描述与来源。

## 3.1 范围与批次

建议将 3.1 分为 A（首个 Beta 的稳定性）、B（后续 Beta 的业务功能）、C（先完成方案再决定交付批次）。批次表示先后和准入条件，不预先占用 beta.2 等发布编号；C 不作为 beta.1 的隐含承诺。范围涵盖客户端体验，但代码仍落在实际所属仓。

| 层次 | 修改与交付归属 | 范围边界 |
| --- | --- | --- |
| 客户端壳 | nuwax-client overlay、打包与安装脚本 | 宿主桥、登录生命周期、加载恢复、升级、权限与系统名称 |
| 共用 PC 页面 | nuwax | Web 与桌面内嵌页共用：登录反馈、左侧任务状态、上传发送、图片预览、昵称引导、页面布局 |
| IM / 资料库 | nuwax-im / nuwax-repo-web，按现行分工协调 | 截图草稿、消息编辑、文件预览/入库、联系人和资料库交互；独立提交后再更新主站引用 |
| 引擎 / 后端 | 对应服务与 harness 仓 | 初始化、任务/发布结果、会议令牌、文件权限、成员角色等契约；壳内不另造实现 |

前端改动需经其正常开发分支与 PR 落地，随后核对客户端实际消费的源码、IM/资料库引用与产物。独立仓已修、线上已部署、客户端 pin 已更新、安装包验收是不同状态。

## 实施与验证

### 实施顺序与首批输入

1. 先建立 A1/A2/A3/A5 的最小复现：失败版本、同次操作的脱敏请求/安装/采集日志、域名与 OS。A6 核对 build/publish、Git/文件持久化各阶段响应。无需等待旧 stable 归档。
2. 可立即从已有证据继续 A4 的源码追踪和 A7 的候选包验收准备；共享页面与独立微应用按上述归属拆出提交。B1/B3 确认小边界后实施，B2 等接口，B4 等原入口约束解除。
3. 每个工作包完成都记录“实现提交/PR → 客户端实际 pin → 自动检查 → 候选版本 → 实测环境与结果”，另列待验证和跨团队依赖；本计划内更新即可。不因需求同组就合并关闭所有问题编号。
4. 本轮仅梳理范围，尚未实施上述新增功能；原指派清单的完成状态保持，后续按实际交付证据更新。
