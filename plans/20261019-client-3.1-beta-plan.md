## 3.1 范围与批次

将明确指派的范围分为 A（首批稳定性）、B（功能与页面修复）、C（已指派的方案工作）。批次表示先后，不预先占用 beta.2 等发布编号；方案工作不等于首包实现承诺。范围涵盖客户端体验，代码仍落在实际所属仓。

| 层次 | 修改与交付归属 | 范围边界 |
| --- | --- | --- |
| 客户端壳 | nuwax-client overlay、打包与安装脚本 | 宿主桥、登录生命周期、加载恢复、升级、权限与系统名称 |
| 共用 PC 页面 | nuwax | Web 与桌面内嵌页共用：左侧任务状态、文件预览、昵称引导、对话展示与订阅布局 |
| IM / 资料库 | nuwax-im / nuwax-repo-web，按现行分工协调 | 已指派功能涉及的截图草稿、文件预览/入库；独立提交后再更新主站引用 |
| 引擎 / 后端 | 对应服务与 harness 仓 | 已指派工作需要的初始化、执行结果、文件权限与协议契约；壳内不另造实现 |

前端改动需经其正常开发分支与 PR 落地，随后核对客户端实际消费的源码、IM/资料库引用与产物。独立仓已修、线上已部署、客户端 pin 已更新、安装包验收是不同状态。

## 实施与验证

### 实施顺序与首批输入

1. 先建立 A1/A2/A3 与 B5 的最小复现：失败版本、同次操作的脱敏请求/安装/执行日志、域名与 OS；A4 利用既有证据准备候选包回归。无需等待旧 stable 归档。
2. 共享页面与独立微应用按上述明确指派范围拆提交；B1/B3 收敛小边界，B2 复用接口，B4 沿用原入口限制，B6 仅处理既有协作分工；C1–C3 完成方案后再安排实现。
3. 每个工作包完成都记录“实现提交/PR → 客户端实际 pin → 自动检查 → 候选版本 → 实测环境与结果”，另列待验证和跨团队依赖；本计划内更新即可。不因需求同组就合并关闭所有问题编号。
4. 范围梳理后，用户授权优先实施 A2.1；其他工作包尚未开始，原指派清单的完成状态保持，后续按实际交付证据更新。

### A2.1 Windows 首次安装提速

目标是缩短用户从启动安装器到安装完成、首次打开可用的等待，并消除长时间无反馈。保留首次安装向导；与应用内一键升级分别验收。

| 阶段 | 要做的工作 | 交付证据 |
| --- | --- | --- |
| 首装基线 | 在自有干净 Windows 环境/快照安装固定基线包，分记安装器启动到向导、点击安装到文件落盘、注册/快捷方式到完成、首次启动到登录页可交互 | 包 SHA/大小、安装后文件数/体积、OS/CPU/磁盘/架构、签名与安全软件状态、各阶段耗时；用户停留向导或授权的时间单列 |
| 解压与写盘 | 沿实际安装器检查归档解压、临时目录和最终目录写入，定位重复解压/复制；复用已有 ZIP/7z QA 对比入口，比较解压时间、临时空间和包体积 | 同一源码/资源集合的实际候选包对比；同时评估下载增量和升级行为，再决定采用的归档策略。QA 对比开关存在不代表公开包已采用 |
| 随包资源 | 统计高文件数/大体积资源，确认重复或仅开发/构建使用的内容；只裁掉有来源与运行时依赖证据的冗余文件 | 资源清单与前后差异；终端、文件、截图、Computer Use 及卸载清单完整，不能通过漏装必需资源换取速度 |
| 首次启动与反馈 | 区分安装耗时和首次启动的初始化耗时，针对实测瓶颈减少重复准备/校验；给确实耗时的阶段可理解的进度和失败诊断 | 安装完成后可正常启动/登录，无长时间无反馈；进度改善与实际耗时改善分别记录 |
| 对照验收 | 同机、同类干净快照、同签名/安全软件条件下，对基线和优化候选分别重复计时并比较中位数；优先 Windows x64，ARM 仿真结果单列 | 列出各阶段及总耗时前后值、改善比例、包体积变化与失败情况；按测得基线制定提速目标。当前没有已完成的首次安装提速结论，不引用历史升级耗时代替 |

实施顺序：先测量并确定主耗时阶段，再提交对应优化，最后用实际候选包验证。首次安装、覆盖升级、失败恢复与卸载分别记录，保全、签名和发布校验继续有效；本轮不创建发布或更新源。

### 3.1.0-beta.1 发布条件

1. 明确本次实际纳入的 A/B 子项，具备对应实现、相关自动化证据与未覆盖范围；未定位的问题继续公开跟踪，不借版本升级标为已修。C 不自动加入首包范围。
2. 变更经 PR 进入 `release/v3.1`。基座、前端和产物 pin 对应且远端可取；overlay、来源授权、认证及发布物完整性检查保持有效。
3. 相关源码检查通过；发布前执行完整社区/商业双轨、前端、桥契约和平台构建门禁。社区测试使用隔离副本。
4. 对实际候选完成登录、普通会话、业务新窗口、文件、截图录屏及安装/升级回归。Windows ARM 仿真、真实 x64、旧 Win10、MSI、系统权限与签名分开记录。
5. 完成需求与验收后，再按 `npm run release -- --version 3.1.0-beta.1 --dry-run` 预检，并根据当时的发布授权创建不可变 tag、经现行流水线发布。预检通过不等于已经发布。
