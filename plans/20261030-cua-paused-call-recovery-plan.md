# Computer Use 暂停调用恢复与 Beta 验证

- 状态：源码修复与本地质量门通过，准备发布 v3.1.0-beta.12；用户已授权修复后发布新的 Beta。
- 现场：2026-10-30 12:58:19 首次观察因 userTakingControl 失败；12:58:26 换窗口重试，13:03:26 才以 MCP 300 秒超时结束。
- 根因：已暂停任务的新调用进入 waitReady，网关的人工作用等待可达任务剩余 15 分钟，超过模型侧请求超时；窗口目标校验位于等待之后。

## 修复范围

1. 已绑定且暂停的任务，新调用及时返回明确原因；提示模型告知用户，禁止换窗口绕过或自动重试。
2. 对恢复、排队、确认等需要保持在途请求的等待设置有界超时，早于上游 300 秒超时；等待结束只结束本次请求，不自动恢复、重放或扩大权限。
3. 继续/停止、取消和连接断开均及时清理等待与原生租约；保留恢复后重新观察的约束。
4. 暂停预览显示清晰状态；操作按钮默认隐藏、悬停或键盘操作时出现，圆角与阴影减轻，透明留白避免原生视图裁切阴影。

- 运行 CUA 定向测试、商业版全量门禁、依赖边界；用真实 Electron 页面检查悬停/键盘与阴影边界。
- 使用 pre-commit-quality-review 做内聚、分层和可维护性自查。
- 仅提交本次 CUA 修复和预览样式；其他浏览器 WIP 保留。
- 从干净工作区固定前端 pin，发布前重新核对已占用 Beta 序号；先 dry-run，再通过根 release CLI 构建五平台并核实公开资产与更新指针。
- 同一问题最多启动 4 次构建；失败保留原 run/SHA 的证据，按规则续跑，不通过换版本绕过上限。

## 已完成证据

- 旧代码下 4 个新增回归用例失败，复现新调用与人工等待悬挂。
- 修复后 MCP 网关真实本地 TCP 测试 43 项通过，包含不同窗口拒绝、60 秒等待策略、恢复后重新观察、取消/停止不重复响应，以及原生 drain 确认前不释放同进程租约。
- 商业版全量：306 文件通过、1 跳过；3790 项通过、18 跳过。依赖边界、数据目录检查和桥契约检查通过。
- 真实 Electron 离屏页面验证：默认隐藏、悬停显示、移开隐藏、键盘聚焦显示、暂停标签、四层堆叠、深色模式；各图像外边缘 alpha ≤ 1，阴影未被视图边界硬裁。
- 自查：等待上限和响应收敛在 MCP 网关维护；任务预算与订阅清理在 Registry 维护；提示集中在 Guidance/Policy，预览样式只改私有页面。未改权限、自动恢复、旧动作重放或其他任务的授权范围。
- 本次是主进程/私有页面源码修改，不改原生 helper/Capture 缓存配方，也不强制冷编。
- 真实安装包/实机验收在构建后进行；本地 TCP 测试中的原生 driver 是模拟进程，不作为实机操作成功的证据。
