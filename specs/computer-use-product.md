# 规格：Computer Use 产品运行闭环

- 对应 intent：`plans/20261013-computer-use-product-intent.md`
- 状态：实现基线；技术决定基于已读源码及用户授权，验收结果另记。

## 需求基线

延续独立 CUA helper、私有端点、工具白名单、一次性授权。工具调用经商业宿主网关统一调度，驱动负责桌面执行，Agent 引擎负责模型规划和对图像/工具结果的理解。

## 方案设计

### 多窗口执行模式（2026-10-19）

- macOS / Windows 显式开启多窗口模式后，每个活跃 ACP prompt 创建独立任务，由用户选择一个应用窗口；绑定不自动执行，点击继续后才放行。旧模式和 Linux 保留原行为。
- 每任务维护独立授权代次、绑定身份、观察额度、预算和历史；最多四个运行任务，其余排队。一个窗口只能归一个任务；同一进程的不同窗口共享执行租约，观察和动作串行，避免进程级焦点及缓存相互覆盖。不同进程可并行。
- 后台首批支持精确元素点击、设值和元素滚动；原生 AX/UIA 能力不足时暂停。通用键盘、像素输入和拖拽需要用户显式切到前台。前台模式取得全局独占权，先暂停并排空其他任务；退出前台不会自动恢复它们。
- 用户激活后台任务的目标窗口时，只暂停该任务。宿主轮询和原生执行前后检查共同阻断接管后的新动作。原生窗口身份包含进程生命周期和窗口生命周期；原窗口关闭或原生 ID 被复用时必须重新绑定。
- 暂停先同步失效宿主许可，再撤销 helper 的任务代次；收到原生在途调用及会话资源排空确认，才释放对应进程租约。排空失败维持停止处理中，不伪造接管成功。全局急停仍退出整个 helper，重新准备后清除旧任务，重新选择目标。
- 等待选窗、人工接管及容量名额期间，MCP 调用保持挂起。恢复不重放旧动作，而是返回要求重新观察的结果，保留同一 ACP 回合继续规划。取消/登出会结束等待并撤销授权。
- 新模式每次写动作后要求新观察；旧模式保留 3.1 的每次观察三次写额度与 ok/refused/uncertain 分类。未验证的成功派发不等于业务成功，也不自动判作不确定失败。
- 窗口工具参数和原生任务上下文均由宿主注入。桌面/应用发现别名转换为目标窗口观察，禁止旁路的原生协议、剪贴板、浏览器、录制和模型自定义会话生命周期工具。窗口列表只提供给可信控制界面。
- 控制面板支持逐任务选窗、暂停、继续、停止和模式切换；全局急停保留。每窗口标记不接收鼠标、不取焦点，并跟随原生虚拟光标颜色；窗口遮挡/隐藏时隐藏标记。标记与暂停确认是不同状态。
- helper 通过能力握手确认任务协议，能力缺失即拒绝启用；不向旧 helper 静默降级。协议和 UI 验证与真实软件、系统授权、签名安装包验收分开，见 [本轮证据](../docs/acceptance/20261019-computer-use-multiwindow.md)。

### 架构落点

1. `main/features/computer-use/taskController` 为不依赖 Electron 的任务状态机，管理一个任务的控制方、动作预算、暂停/恢复后新观察要求、终止代次及脱敏历史；多窗口模式由 `taskRegistry` 管理实例和租约。
2. `cua/mcpGateway` 将每个 MCP stdio 连接转发至 helper；宿主在工具调用前强制检查状态与控制权，在响应后记录结果。随机私有本机端点和能力文件鉴权，无 TCP 监听。MCP 初始化/发现保持协议透传；失败关闭，不能旁路降级成原始 MCP 配置。
3. `computerUse` 保留安装/系统授权/驱动策略职责，新增运行态事件及控制动作。认证停止入口同步撤销操作代次，再等待资源清理，正常登出不清除用户偏好。
4. `CuaControls` 在宿主显示活动/暂停/故障状态、动作和记录；独立 `controlWindow` 跨应用常驻、不抢焦点，最小 preload 和精确 sender/frame/url 校验。设置页提供范围选择、恢复和自检；托盘和全局快捷键提供额外急停入口。
5. `sessionAuthority` 由 ACP 引擎在 new/load/resume 时签发每会话凭据，仅 prompt 活跃期可执行。取消、删除、销毁先撤权，再等待引擎/系统清理；同项目复用引擎也不能复用另一个会话的控制权。
6. `windowScope` 同时生成宿主参数约束和 helper 托管 YAML，限定窗口仅开放观察、元素点击、设值和滚动。范围变更停止旧任务并验证新策略。

### 数据与契约

- 任务状态：idle/running/paused/stopped/failed/completed；包含 taskId、revision、步骤、时间、原因与停止处理中标记；owner 仅保留在主进程，不外传。
- 客户端控制：getRuntime、pause、resume、stop、recover、selfTest、exportDiagnostics、clearHistory、listWindows、setScope；状态事件 `cua:runtime` 只发往宿主 renderer。
- MCP 控制身份来自宿主签发的 ACP 会话凭据和 prompt 代次，不信任模型传入的 session 标签；闲置/已取消/已销毁会话无法执行工具。无凭据的旧版全局 MCP 入口只允许协议握手，不具备桌面调用权。
- 普通用户内容、截图、剪贴板、URL、窗口标题、工具参数、模型密钥不进入审计；只记录工具名/时间/耗时/结果码。
- 首次、恢复后以及每次写动作后必须成功执行观察工具，再允许下一次写动作；不自动重放已发送动作，停止后关闭旧连接。禁用可绕过逐步检查的 `replay_trajectory`。
- 默认 100 次工具调用、15 分钟总时限、5 分钟无操作暂停；连续相同写动作超过 3 次暂停，穿插观察不会重置重复次数。恢复不能重置预算。
- 凭据最多 256 份、网关最多 32 个连接；引擎销毁清理凭据文件，启动清理已退出进程的已知 capability 文件。正常 prompt 完成回收 helper 传输租约，以结束录制、光标等会话资源。显式录制输出仍归调用者管理，不删除未知用户文件。
- 附带 CUA 权限的 prompt 不自动重试整段请求，避免响应丢失后重放桌面动作。
- 旧模式暂停会停止驱动进程；多窗口模式仅撤销并排空对应任务。恢复保留 Agent 侧连接，私下重新初始化 helper 的 MCP 连接，握手完成才允许继续。
- 模型连接测试必须消费实际图像并检查有效模型响应；历史明文密钥迁移至系统加密存储，界面不回传已有明文。

### 平台/引擎矩阵

| 行为 | macOS | Windows | Linux |

## 运行预览与人工接管

- 多窗口模式只使用宿主统一画中画浮窗，主页面不再叠加第二个任务管理浮层，管理入口保留在设置页：首次自动展开并记忆用户偏好；默认直接呈现目标窗口画面，透明外层不加重复标题栏或管理面板；任务缩略图向左下错位叠放。关闭/接管位于画面外侧上方，悬停或键盘聚焦显示任务控制，暂停状态保持可辨识。任务菜单承载选窗、前后台切换及恢复，详细设置默认折叠。
- 关闭/收起预览只缩为控制条，不能停止任务；点击控制条中的任务名或展开按钮恢复预览。停止当前任务、停止全部任务、托盘与全局快捷键保留明确停止语义；后续运行态更新不能强制展开。
- 窗口状态胶囊显示 Nuwax、任务状态和任务颜色，点击只打开任务预览。目标被遮挡、最小化或过小时隐藏，不抢目标窗口焦点。
- `showTaskPreview(taskId)` 打开对应任务的统一浮窗；`takeOverTask(taskId)` 同步撤销写权限，等待原生在途动作排空后精确激活原窗口。无法确认交还、窗口失效或激活失败时仍保持暂停，不回退为任意活动窗口。
- 预览与写权限分离：暂停任务允许查看已绑定窗口；帧不是模型观察证据，不增加/重置动作预算或闲置时限。模型恢复后仍必须重新观察。
- helper 以 `nuwax_window_preview=1` 声明能力；预览和接管控制只由经过端点鉴权的宿主调用，不暴露为模型 MCP 工具。旧 helper 保留任务控制并提示更新。
- macOS 预览只使用内存 ScreenCaptureKit，Windows 只使用目标窗口 WGC。不可用时明确提示，不启用整桌面裁切、磁盘截图或前台置顶兜底。
- 仅展开且可见的选中任务持续采集，默认 2 FPS、最长边 960、JPEG 不超过 512KiB，最多一帧在途。预览响应独立上限 1MiB，不扩大原控制响应的 64KiB 上限。
- 每帧绑定 taskId、bindingId、epoch、序号和采集时间，采集前后以及显示前均校验；任务切换不展示旧目标帧。只保留选中任务最新帧及最多两张其他任务最近缩略图，后台卡片显示采集时间、不是实时画面。
- 收起、最小化和 renderer 退出停止采集；锁屏/休眠、登出、停止、目标代次失效立即清理画面。解锁只允许重新查看仍有效的授权窗口，不自动恢复任务执行。
- 帧仅通过最小 preload 发到可信控制浮窗，不进入运行态、模型历史、诊断、网络上传或持久化存储。位置与展开偏好可以持久化，不保存目标窗口身份或内容。

## 异常与失败场景

- 并行调用/多连接：旧模式只允许唯一任务所有者；多窗口模式使用窗口唯一租约、每任务单飞、同进程串行及前台全局独占约束。
- 断流、超时、进程退出：终止或暂停任务，释放控制权，不自动重试写动作。
- 停止发生在启动/授权/重连期间：同步撤销代次；异步返回不能注入 MCP 或重新激活任务。
- 宿主退出：网关断开并清理子进程，驱动在退出清理链停止。
- 恢复：保持同一控制方，重新拉起驱动，要求新观察；不自动操作桌面。
- 数据清理：只能删除明确托管的诊断数据，不递归删除未知用户文件。

## 测试计划

- 真实模型基准必须复用实际 Agent 与产品控制链，并固定任务/模型/运行时/helper/应用版本及前后台、输入模态；模型自行规划，成功由独立业务结果判定。合成 GUI、系统/第三方应用、签名安装包和长稳验收分开，不以夹具成绩替代发布验收。
- 阻断、失败、人工介入和未执行任务保留在覆盖分母中；报告成功率、动作步数、P50/P95 耗时、失败原因和每成功任务成本。未知 usage/价格不记零；预览帧不进入模型证据或成本计算。
- 模型侧观察必须保留驱动返回的精确快照标识，并告知宿主当前实际执行模式。只消费 MCP 文本/图片的 Agent 也要能获取 `snapshot_id`；宿主不生成替代标识，不把迟到、失败或预览响应转为有效观察。写入只能使用最近观察中的 token，或快照 ID 与索引组合；模式说明不授予权限，实际许可仍由宿主与原生校验。
- 双平台真实模型试点优先用于发现失败原因，再进行同口径优化复跑；行业排名需要另设可比外部基准，内部成功率门槛不能直接等同于第一梯队。

- 状态机：抢占/释放、重复动作、预算、过期回包、暂停/恢复、观察门禁、历史脱敏。
- 网关：协议透传、认证拒绝、断线、并行、错误结果、终止和背压边界。
- CUA：保留既有 26 项测试，补生命周期取消、故障状态与恢复。
- UI/IPC：宿主来源校验，状态订阅卸载、动作与错误文案、多语言。
- 商业域测试与构建；社区域在独立隔离副本运行；真实桌面与签名包验收结果分开记录。

## 已否决的备选方案

- 仅添加暂停按钮：不能阻断 MCP 调用，无真实控制效果。
- 每次操作弹确认：违背现有一次授权产品决定。
- 超时自动重试所有工具：可能重复提交、发送或删除。
- 将本地设置的 VLM 文本 ping 视为端到端验收：未验证图片能力，也没有任务链路证据。

## 已实现范围与发布验收边界

- 已实现可信会话隔离、窗口参数约束和驱动策略、跨应用浮窗、生命周期资源回收。对应自动化证据见 `docs/acceptance/20261013-computer-use-product.md`。
- 窗口模式限制直接工具目标。它不是 OS 沙箱：目标应用自身响应点击后打开其他窗口/应用属于该应用行为；禁止使用像素、键盘、剪贴板和浏览器工具绕过目标。重启只保留窗口模式偏好，必须重新选择实际窗口。
- 模型规划复用会话 Agent；界面“任务结束”不代表业务结果成功。真实模型、账号、系统授权、多屏、跨平台与签名安装行为由发布验收确认。
- 本地功能验收候选与正式发布区分：不创建公开版本 tag，不改更新源。正式分发仍使用既有签名/公证与不可变 tag 流程。
