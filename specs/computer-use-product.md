# 规格：Computer Use 产品运行闭环

- 对应 intent：`plans/20261013-computer-use-product-intent.md`
- 状态：实现基线；技术决定基于已读源码及用户授权，验收结果另记。

## 需求基线

延续独立 CUA helper、私有端点、工具白名单、一次性授权。工具调用经商业宿主网关统一调度，驱动负责桌面执行，Agent 引擎负责模型规划和对图像/工具结果的理解。

## 方案设计

### 架构落点

1. `cua/taskController` 为不依赖 Electron 的任务状态机，管理唯一控制方、动作预算、暂停/恢复后新观察要求、终止代次及脱敏历史。
2. `cua/mcpGateway` 将每个 MCP stdio 连接转发至 helper；宿主在工具调用前强制检查状态与控制权，在响应后记录结果。随机私有本机端点和能力文件鉴权，无 TCP 监听。MCP 初始化/发现保持协议透传；失败关闭，不能旁路降级成原始 MCP 配置。
3. `computerUse` 保留安装/系统授权/驱动策略职责，新增运行态事件及控制动作。认证停止入口同步撤销操作代次，再等待资源清理，正常登出不清除用户偏好。
4. `CuaControls` 在宿主显示活动/暂停/故障状态、动作和记录；独立 `controlWindow` 跨应用常驻、不抢焦点，最小 preload 和精确 sender/frame/url 校验。设置页提供范围选择、恢复和自检；托盘和全局快捷键提供额外急停入口。
5. `sessionAuthority` 由 ACP 引擎在 new/load/resume 时签发每会话凭据，仅 prompt 活跃期可执行。取消、删除、销毁先撤权，再等待引擎/系统清理；同项目复用引擎也不能复用另一个会话的控制权。
6. `windowScope` 同时生成宿主参数约束和 helper 托管 YAML，限定窗口仅开放观察、元素点击、设值和滚动。范围变更停止旧任务并验证新策略。

### 数据与契约

- 任务状态：idle/running/paused/stopped/failed/completed；包含 taskId、revision、步骤、时间、原因与停止处理中标记；owner 仅保留在主进程，不外传。
- 客户端控制：getRuntime、pause、resume、stop、recover、selfTest、exportDiagnostics、clearHistory、listWindows、setScope；状态事件 `cua:runtime` 只发往宿主 renderer。
- MCP 控制身份来自宿主签发的 ACP 会话凭据和 prompt 代次，不信任模型传入的 session 标签；闲置/已取消/已销毁会话无法执行工具。无凭据的旧版全局 MCP 入口只允许协议握手，不具备桌面调用权。
- 普通用户内容、截图、剪贴板、URL、窗口标题、工具参数、模型密钥不进入审计；只记录工具名/时间/耗时/结果码。
- 首次、恢复后以及每次写动作后必须成功执行观察工具，再允许下一次写动作；不自动重放已发送动作，停止后关闭旧连接。禁用可绕过逐步检查的 `replay_trajectory`。
- 默认 100 次工具调用、15 分钟总时限、5 分钟无操作暂停；连续相同写动作超过 3 次暂停，穿插观察不会重置重复次数。恢复不能重置预算。
- 凭据最多 256 份、网关最多 32 个连接；引擎销毁清理凭据文件，启动清理已退出进程的已知 capability 文件。正常 prompt 完成回收 helper 传输租约，以结束录制、光标等会话资源。显式录制输出仍归调用者管理，不删除未知用户文件。
- 附带 CUA 权限的 prompt 不自动重试整段请求，避免响应丢失后重放桌面动作。
- 暂停会停止驱动进程；恢复保留 Agent 侧连接，私下重新初始化 helper 的 MCP 连接，握手完成才允许继续。
- 模型连接测试必须消费实际图像并检查有效模型响应；历史明文密钥迁移至系统加密存储，界面不回传已有明文。

### 平台/引擎矩阵

| 行为 | macOS | Windows | Linux |
|---|---|---|---|
| 控制网关 | 私有 UDS | 随机命名管道+能力鉴权 | 私有 UDS |
| 急停 | 全局快捷键+界面 | 同左 | 注册失败明确显示 |
| 系统授权 | 既有 helper AX/SR 探测 | 不伪造系统授权行 | Wayland 实机另验 |
| 锁屏/休眠 | 暂停并阻断新动作 | 同左 | Electron 能力范围内 |

## 异常与失败场景

- 并行调用/多连接：只允许唯一任务所有者，写操作单飞，其他方返回结构化忙碌错误。
- 断流、超时、进程退出：终止或暂停任务，释放控制权，不自动重试写动作。
- 停止发生在启动/授权/重连期间：同步撤销代次；异步返回不能注入 MCP 或重新激活任务。
- 宿主退出：网关断开并清理子进程，驱动在退出清理链停止。
- 恢复：保持同一控制方，重新拉起驱动，要求新观察；不自动操作桌面。
- 数据清理：只能删除明确托管的诊断数据，不递归删除未知用户文件。

## 测试计划

- 状态机：抢占/释放、重复动作、预算、过期回包、暂停/恢复、观察门禁、历史脱敏。
- 网关：协议透传、认证拒绝、断线、并行、错误结果、终止和背压边界。
- CUA：保留既有 26 项测试，补生命周期取消、故障状态与恢复。
- UI/IPC：宿主来源校验，状态订阅卸载、动作与错误文案、多语言。
- 商业域测试与构建；社区域在独立隔离副本运行；真实桌面与签名包验收结果分开记录。

## 已否决的备选方案

- 仅添加暂停按钮：不能阻断 MCP 调用，无真实控制效果。
- 每次操作弹确认：违背现有一次授权产品决定。
- 超时自动重试所有工具：可能重复提交、发送或删除。
- 将本地设置的 VLM 文本 ping 视为端到端验收：未验证图片能力，也没有任务链路证据。

## 已实现范围与发布验收边界

- 已实现可信会话隔离、窗口参数约束和驱动策略、跨应用浮窗、生命周期资源回收。对应自动化证据见 `docs/acceptance/20261013-computer-use-product.md`。
- 窗口模式限制直接工具目标。它不是 OS 沙箱：目标应用自身响应点击后打开其他窗口/应用属于该应用行为；禁止使用像素、键盘、剪贴板和浏览器工具绕过目标。重启只保留窗口模式偏好，必须重新选择实际窗口。
- 模型规划复用会话 Agent；界面“任务结束”不代表业务结果成功。真实模型、账号、系统授权、多屏、跨平台与签名安装行为由发布验收确认。
- 本地功能验收候选与正式发布区分：不创建公开版本 tag，不改更新源。正式分发仍使用既有签名/公证与不可变 tag 流程。
