# 规格：Windows 升级安装与恢复

- 日期：2026-09-23；对应 intent：`plans/20260923-windows-upgrade-install-intent.md`。
- 状态：已按用户接手指令授权实施；安装包与真实 Windows 验收待记录。

## 1. 现状与原因

截图显示 electron-builder 25.1.8 的 NSIS assisted 安装器报 `appCannotBeClosed`。默认 `CHECK_APP_RUNNING` 主要按应用映像名关闭进程，短重试后仍发现 `Nuwax.exe` 就提示用户手动关闭。Electron 应用还会启动子进程；主进程关闭链运行较慢或子进程仍存活时，安装目录可能继续被占用。

## 2. 行为契约

1. 手动安装且检测到应用运行时，保留 NSIS 原有 `appRunning` 提示；应用内更新保持静默关闭行为。
2. 先请求关闭 `Nuwax.exe` 及其子进程，并等待最多 10 秒，给应用的有序退出清理留出时间。
3. 仍在运行时，最多三次强制结束 Nuwax 进程树并复查。
4. 仍无法结束（例如应用以更高权限运行）时，保留 `appCannotBeClosed` 的重试/取消提示；不自动请求 UAC。
5. per-user 安装的关闭命令只匹配当前用户名，并排除安装器自身 PID；per-machine 分支沿用 electron-builder 的全用户进程查询语义。

## 3. 范围

- 改动：外层仓库 `overlay/crates/agent-electron-client/build/` 的商业 NSIS 编排、恢复/卸载 PowerShell，以及对应夹具。
- 不改：基座 submodule、前端、应用服务生命周期、NSIS 安装类型与 UAC 策略。

## 4. 验收

| 编号 | 场景 | 预期 |
|---|---|---|
| W1 | 应用已退出 | 安装器继续安装 |
| W2 | 普通权限应用运行、手动启动安装 | 保留运行提示，应用退出后安装继续 |
| W3 | 普通权限应用处于更新/清理退出阶段 | 安装器最多等待 10 秒后检查状态，不因短暂清理延迟立即失败 |
| W4 | 普通权限应用不响应 | 安装器强制结束应用及子进程树后继续 |
| W5 | 应用以更高权限运行或重试仍杀不掉 | 显示手动关闭提示；Retry 重试，Cancel 退出安装 |
| W6 | 其他 Windows 用户也运行 Nuwax（per-user 安装） | 不结束其他用户的应用进程 |

自动构建检查与交互式 Windows 安装包验收分别记录；当前代码修改本身不等于 Windows 安装验收通过。

## 5. 异常安装维护与旧版本救援（release/v3.0）

安装、自动升级和卸载只检查当前产品、当前安装路径对应的恢复事务。未完成的事务先恢复或回滚；完成记录核验后清理指针。备份目录确实不存在时，归档该指针及原因，重新保全现存文件并继续；告知用户原备份中的文件无法保证找回。权限不足、磁盘不可用、重解析路径和文件冲突均保留现场并返回失败，不能等同于备份不存在。

备份存在而清单缺失或损坏时，普通安装和自动升级停止。完整包的维护页提供“修复或升级”和“卸载”，用户可明确勾选保留旧备份、另建事务修复。此选择只归档当前路径的旧指针，不删除旧备份。静默支持 `/REPAIR` 表达同一明确选择、`/UNINSTALL` 表达先修复再卸载；二者不能与 `--updated` 混用。多个登记路径冲突时必须明确选择已有候选，不能据此接管任意新目录。

维护保持原安装位置和 per-user/all-users 范围，同时核对产品私有键、卸载命令和目录载荷；标准卸载项 `InstallLocation` 为空本身不代表损坏。`/D=` 保留 NSIS 解析后的完整路径，包括空格和正斜杠，并在写入前拒绝磁盘根目录、用户目录根及系统目录。保全前检查同卷空间，保存两个产品登记键的带类型快照与校验摘要。

旧卸载器已删除全部登记而新载荷或恢复尚未完成时，原目录重试必须先只读核验该目录的活动事务、登记快照摘要、两个产品键和原路径，再沿用快照中的安装范围。per-user 快照另记录并核对原账户 SID；显式选择另一范围、同范围已有不同登记、身份信息不足或记录损坏时停止并保留现场。残留登记允许缺少已删除的键或值，但仍存在的每个值及类型必须与快照一致；安装目录已被删除而恢复仍待完成时，不能提前清掉原私有路径提示。开始保全前再次核验，并恢复原登记及缺失的卸载入口；不能把有待恢复文件的原目录当成全新安装后返回成功。此检查不扫描其他目录；登记全失时，用户须选择原安装目录。历史 per-user 快照缺少可核验的账户身份且登记也已消失时，需支持人员核对，不自动推断归属。

已有安装收到不同于所选登记位置的 `/D=` 时停止，维护不迁移安装目录。显式 `/currentuser`、`/allusers` 在安装和卸载入口重新核对，避免旧模板默认范围覆盖调用者选择。all-users 维护不顺带保全或卸载另一个 per-user 副本；其他范围的已登记副本即使可执行文件缺失，其快捷方式也保留。两个范围指向同一物理目录时停止；两个独立副本并存而静默调用没有指定范围或路径时要求明确选择。

新安装器先保全全部现存文件，再尝试运行旧卸载器。缺失、不能启动或返回非零时，只有核验保全完成且原目录仅剩未改变的卸载器后，才允许接管并写入完整新载荷与新卸载器。失败时独立恢复登记和缺失的旧卸载入口；文件恢复冲突保留双方并返回失败。选择卸载时运行新卸载器并返回其真实结果，期间不启动客户端。

默认保留 `.nuwax`、设置、会话、工作区及未知安装目录文件，删除数据仍需在新卸载器明确勾选。新版清单只用于卸载新版自己的载荷，不能推断旧文件可删除。NuwaClaw、nuwa-cli、外部项目及共享目录不纳入清理；快捷方式与开机启动项按产品 AppId 和实际目标路径共同匹配。成功备份继续沿用最近一次及七天保留策略；未知、未完成或被修改的旧备份保护并输出原因。

停用 vendor 后置的按名称删除默认快捷方式和撤销共享 AppUserModelId。更新时保留快捷方式，由父安装器修复；恢复被模板覆盖的、指向另一已登记副本的默认别名。先修复再卸载不创建或改名此类别名。安装后直接启动所选程序路径，不通过可能指向其他副本的快捷方式启动。

普通卸载与 `--updated` 都只移除卸载器自身的载荷清单，不递归移除整个安装目录。更新模式先核验父安装器的保全记录，再按清单删除；不会把父事务已保全的文件提前恢复到待写入目录。直接调用更新模式也保留未知文件；保全未完成或登记无法核验时停止。

诊断保存在 `%TEMP%\Nuwax-installer-recovery.log` 和 `Nuwax-installer-recovery-events.jsonl`，包含阶段、原始错误、路径、范围及状态位置；原安装目录旁保留事务清单和归档原因。退出码 2 必须结合阶段日志定位，不能一概解释为程序仍运行。沿用现有安装实例限制和按安装路径的恢复互斥，不通过窗口猜测锁持有者。

PowerShell 内联 C# 的编译依赖绑定到已加载的 .NET 程序集绝对路径，避免 NSIS 插件目录中的原生 `System.dll` 被误当成托管依赖。卸载和备份清理夹具均保留此同名文件回归。

验证入口：`scripts/test-installer-recovery.ps1`、`test-installer-registration.ps1`、`test-installer-backup-retention.ps1`、`test-uninstall-data.ps1`，以及 `scripts/acceptance/windows-uninstall-fixture.py`。`scripts/acceptance/windows-installer-recovery.cjs` 必须在 Windows 使用固定 electron-builder 25.1.8 构建随机产品身份的无签名合成载荷，再运行 `scripts/test-installer-maintenance.ps1` 和 `test-installer-pending-recovery.ps1` 分别检查两种范围。旧 tag 安装器源码使用相同 QA 身份重新编译后，可用 `scripts/test-installer-legacy-upgrade.ps1` 验证兼容性。此夹具不能代替签名完整包、真实 3.0.16/3.0.19 载荷、交互 UAC、物理离线磁盘及实际自动更新端到端验收。

## 6. 修复版本交付后的操作方案

以下维护入口需要包含本次修复的完整安装包；历史 3.0.16/3.0.19 包不提供这些新选项。

1. 用原 Windows 账号运行已验签的完整包，确认原安装位置及安装范围。需要升级或恢复使用时选择“修复或升级”；原卸载入口不能使用时选择“卸载”，安装器会修复卸载入口后接着卸载。
   若应用和卸载项均已消失，但原目录旁仍有活动恢复记录，仍选择原目录；安装器核验记录后恢复原范围和个人文件。无法确认原账户或记录身份时先保留现场，由支持人员核对。
2. 默认保留本地数据。只在确实需要清除当前账号数据时，在新卸载向导勾选删除数据。原安装目录中的未知文件、外部项目和其他产品保持原位。
3. 提示旧备份清单损坏、恢复冲突或安装只剩部分文件时，核对安装路径，再明确勾选“保留旧备份和现存文件，另建事务修复”。旧备份仍在原安装目录旁，之后可根据归档原因和事务清单找回文件。若备份目录已经丢失，安装器会归档失效指针并继续，丢失备份中的独有文件无法保证找回。
4. 遇到权限、占用、空间不足或磁盘不可用时，保存两份 TEMP 诊断日志与安装目录旁的恢复材料，按日志阶段解除具体问题，再重跑完整包。多个登记位置冲突时明确选择原目录；不能确认时交由支持核对私有登记和卸载命令。

企业静默维护可使用新完整包 `/S /REPAIR /currentuser /D=原安装目录`；所有用户范围使用 `/allusers`。需要先修复再卸载时再加 `/UNINSTALL`。`/D=` 必须放在参数末尾。静默卸载仍保留数据；明确删除数据需使用交互卸载向导。自动升级失败时，支持人员可从日志的 `Inspect`、`Prepare`、`Detach`、`Restore`、`ResolvePath`、`Uninstall` 等阶段定位原因。

### Beta.3 已知边界

当前用户范围已复现：原安装目录整体被旧卸载器删除、只剩产品私有登记且重试未指定 `/D` 时，安装器返回 2 并保留恢复材料。此时用原账户指定原目录，例如 `/S /currentuser /D=原安装目录`；已有有效事务时先不加 `/REPAIR`，让安装器正常续接恢复。该参数组合已在相同生产 hook 的原生合成包验证：修复返回 0、原工作区恢复、完整载荷摘要一致、活动标记清除；再加 `/UNINSTALL` 也返回 0 并保留工作区。所有用户范围的此项无 `/D` 边界及签名完整包仍待验收。

用户已要求先交付 Beta 验证；此已知问题与待验收状态随 Beta.3 记录，后续证据或修复不改写已冻结的版本标签。
