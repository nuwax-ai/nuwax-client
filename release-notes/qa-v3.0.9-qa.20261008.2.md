# Nuwax 3.0.9-qa.20261008.2 独立 QA 验收包

为 2026-10-09 真机验收提前构建。本候选只作为 Actions 验收资产提供，逻辑构建身份为 `qa-v3.0.9-qa.20261008.2`。不创建正式发布 tag，不公开 Release，不更改更新指针。正式 Beta 序列仍保留 `3.0.9`；应用 QA 版本低于后续正式 `3.0.9`，能够识别后续正式更新。

## 本轮变更

- macOS QA 构建：原生数字版本保留3.0.9，DMG文件名显式保留完整QA编号及对应架构；签名、公证、Gatekeeper和来源清单门禁继续严格执行。

- Windows QA 构建：使用 CI 自有临时短目录，避免长 QA 输出路径撞上 WiX 文件访问边界。包名和应用 QA 编号不变，所有集成资源保留；前一 QA 的 260 字符路径失败记录保留，待新构建核验。

- Windows：恢复用户工作区时如果目标目录冲突，保留恢复标记及原数据，阻止新安装覆盖未完成恢复，冲突解除后可重试。
- Windows QA：在保留全部集成资源的前提下，NSIS EXE 使用 ZIP 直接解压候选（MSI 单独验证兼容性），减少临时展开后整包复制；需要同机实测速度和失败恢复，尚未证明安装已提速。
- 客户端：桌面项目列表响应跨设备发起会话，并处理分页刷新竞态；侧栏宽度不足时隐藏不可读的账号姓名。

## 平台

Windows x64（Beta 未签名 EXE）、macOS arm64/x64（CI 签名及公证门禁）、Linux x64/arm64。所有平台使用相同 client/shell/frontend 冻结源码，分别记录包哈希。

## 明日验收

1. Windows 新安装：记录开始、解压、完成及首次启动耗时，用 NSIS EXE 与原 Beta 3.0.8 同机比较。两版包含源码差异，属于版本对照，不是相同 payload 的严格归档 A/B 实验。
2. Windows 卸载：确认原报错能否复现，检查是否仍有残留；本候选尚未盲改独立卸载策略。
3. Windows 恢复冲突、占用、权限不足、磁盘不足和中断：在专用测试目录确认数据保全，不清理真实用户数据。
4. 全平台：安装、启动、登录、默认服务、Node/Git/uv/ACP/MCP/Computer Use 随包能力及原有工作区。
5. 跨设备新会话、项目列表分页刷新和窄侧栏账号显示。

更新链、真实安装行为和签名接受结果分别验收。CI 通过不代表用户已验收；全部资源当前保留，资源冗余候选尚未裁剪。

## 编号与后续更新

Mac/Windows 原生数字版本字段使用 `3.0.9`，应用内部使用完整 QA 编号；Linux 包管理版本由 builder 转为 `3.0.9~qa.20261008.2`。Windows MSI 已允许同数字版本升级，但 QA → 后续正式版本的覆盖安装仍要单独验收。CI 产物只保留 7 天，请为明日测试保留对应安装包及来源清单。
