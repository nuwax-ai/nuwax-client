# Nuwax 3.2.0-beta.6

本轮把引擎升到 nuwax-harness 0.18.53、适配器升到 1.2.45，集中修复长会话的上下文预算与错误提示。

- 上下文预算不再被模型的「理论输出上限」压死。此前模型目录声明输出上限 384k、而网关实际窗口只有 243k，引擎把两者直接相加判定超窗，导致任何消息（哪怕一句「你好」）都报 “ran out of room”，压缩降级后仍然失败。现在输出预留按窗口剩余空间钳制，只有历史本身超过窗口才算超窗。
- 三条协议线（Chat / Anthropic / Responses）统一把发给网关的输出上限钳制到窗口一半，避免把网关必然拒绝的超大 max_tokens 发出去。
- 上下文窗口与输出上限改为按平台下发的参数生效：`OPENCODE_MAX_CONTEXT_TOKENS` / `OPENCODE_MAX_TOKENS` / `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX` 都能被正确读取，宿主显式指定的值仍然优先。
- 恢复会话时不再把历史上的「压缩会话」作为工具调用卡片展示；同一轮内重复的失败提示只显示一次。
- 超窗错误现在会带上实际数值（估算 token、窗口、输出预算、请求字节），便于定位是历史过大、图片预算过高还是窗口偏小。
- 本地联调：`make harness-local` 不再让资源准备覆盖刚同步进去的本地构建引擎；准备阶段失败时会指出具体命令与输出尾部，而不是只报 “npm failed (1)”。

引擎与适配器版本：nuwax-harness 0.18.53、nuwax-harness-acp-ts 1.2.45。

验证：deepseek-flash 长会话恢复后可正常对话（此前必失败），识别图片、命令执行与工具调用链路正常；引擎 wire 测试 132 项、适配器测试 2600 项通过。

Windows Beta 按既有流程发布无签名原包；签名场景使用独立本地签名副本验证。
